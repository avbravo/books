Podrías mejorar el código en qué se cuenta con una aplicación microservicio creada con eclipse micropofile un cliente creado con Jakartaee y un servidor keycloack para autentificación y autorización, crea los ejemplos para payara micro y otro para helidon me, muestrame en ambos casos todos los códigos y archivos de confirmación que necesito para que sea funcional 
___
A continuación, te proporciono un ejemplo completo y funcional de cómo integrar **Keycloak** con una aplicación microservicio creada con **Eclipse MicroProfile**, utilizando **Payara Micro** y **Helidon ME** como servidores. Además, incluiré un cliente creado con **Jakarta EE** para consumir los servicios protegidos.

---

### **1. Configuración de Keycloak**

#### **a. Crear Realm y Clientes**
1. Inicia Keycloak en `http://localhost:8080/auth`.
2. Crea un nuevo realm llamado `microprofile-realm`.
3. Registra dos clientes:
   - `payara-client` (para Payara Micro).
   - `helidon-client` (para Helidon ME).
4. Habilita el mapeo de roles (`admin` y `user`) en los tokens JWT.

### **2. Ejemplo con Payara Micro**

#### **a. Estructura del Proyecto**
```
payara-micro-example/
├── src/main/java/com/example/payara/
│   ├── MyResource.java
│   └── ApplicationConfig.java
├── src/main/webapp/WEB-INF/
│   ├── web.xml
│   └── keycloak.json
├── pom.xml
└── README.md
```

#### **b. Archivo `pom.xml`**
```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>payara-micro-example</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>war</packaging>

    <dependencies>
        <dependency>
            <groupId>jakarta.platform</groupId>
            <artifactId>jakarta.jakartaee-api</artifactId>
            <version>9.1.0</version>
            <scope>provided</scope>
        </dependency>
        <dependency>
            <groupId>org.keycloak</groupId>
            <artifactId>keycloak-adapter-core</artifactId>
            <version>21.0.0</version>
        </dependency>
    </dependencies>

    <build>
        <finalName>payara-micro-example</finalName>
    </build>
</project>
```

#### **c. Archivo `web.xml`**
```xml
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="3.1">
    <login-config>
        <auth-method>KEYCLOAK</auth-method>
        <realm-name>microprofile-realm</realm-name>
    </login-config>

    <security-constraint>
        <web-resource-collection>
            <web-resource-name>Protected Resources</web-resource-name>
            <url-pattern>/api/*</url-pattern>
        </web-resource-collection>
        <auth-constraint>
            <role-name>user</role-name>
            <role-name>admin</role-name>
        </auth-constraint>
    </security-constraint>

    <security-role>
        <role-name>user</role-name>
    </security-role>
    <security-role>
        <role-name>admin</role-name>
    </security-role>
</web-app>
```

#### **d. Archivo `keycloak.json`**
Coloca este archivo en `src/main/webapp/WEB-INF/keycloak.json`:
```json
{
  "realm": "microprofile-realm",
  "auth-server-url": "http://localhost:8080/auth/",
  "ssl-required": "external",
  "resource": "payara-client",
  "public-client": true,
  "confidential-port": 0
}
```

#### **e. Código del Servicio REST**
```java
package com.example.payara;

import jakarta.annotation.security.RolesAllowed;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api")
public class MyResource {

    @GET
    @Path("/admin")
    @RolesAllowed("admin")
    @Produces(MediaType.TEXT_PLAIN)
    public String adminEndpoint() {
        return "Admin access granted!";
    }

    @GET
    @Path("/user")
    @RolesAllowed("user")
    @Produces(MediaType.TEXT_PLAIN)
    public String userEndpoint() {
        return "User access granted!";
    }
}
```

#### **f. Archivo `ApplicationConfig.java`**
```java
package com.example.payara;

import jakarta.ws.rs.ApplicationPath;
import jakarta.ws.rs.core.Application;

@ApplicationPath("/api")
public class ApplicationConfig extends Application {
}
```

#### **g. Ejecutar Payara Micro**
Compila el proyecto y ejecuta Payara Micro:
```bash
mvn clean package
java -jar payara-micro.jar --deploy target/payara-micro-example.war
```

### **3. Ejemplo con Helidon ME**

#### **a. Estructura del Proyecto**
```
helidon-me-example/
├── src/main/java/com/example/helidon/
│   ├── MyResource.java
│   └── Main.java
├── src/main/resources/
│   └── application.yaml
├── pom.xml
└── README.md
```

#### **b. Archivo `pom.xml`**
```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>helidon-me-example</artifactId>
    <version>1.0-SNAPSHOT</version>

    <dependencies>
        <dependency>
            <groupId>io.helidon.microprofile.bundles</groupId>
            <artifactId>helidon-microprofile</artifactId>
            <version>3.0.0</version>
        </dependency>
        <dependency>
            <groupId>io.helidon.security.providers</groupId>
            <artifactId>helidon-security-providers-oidc</artifactId>
            <version>3.0.0</version>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-compiler-plugin</artifactId>
                <version>3.8.1</version>
                <configuration>
                    <source>17</source>
                    <target>17</target>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>
```

#### **c. Archivo `application.yaml`**
```yaml
server:
  port: 8081

security:
  providers:
    - oidc:
        client-id: helidon-client
        client-secret: your-client-secret
        identity-uri: http://localhost:8080/auth/realms/microprofile-realm
        redirect-uri: http://localhost:8081/callback
```

#### **d. Código del Servicio REST**
```java
package com.example.helidon;

import io.helidon.security.annotations.Authenticated;
import io.helidon.security.annotations.RolesAllowed;

import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api")
public class MyResource {

    @GET
    @Path("/admin")
    @Authenticated
    @RolesAllowed("admin")
    @Produces(MediaType.TEXT_PLAIN)
    public String adminEndpoint() {
        return "Admin access granted!";
    }

    @GET
    @Path("/user")
    @Authenticated
    @RolesAllowed("user")
    @Produces(MediaType.TEXT_PLAIN)
    public String userEndpoint() {
        return "User access granted!";
    }
}
```

#### **e. Archivo `Main.java`**
```java
package com.example.helidon;

import io.helidon.microprofile.server.Server;

public class Main {
    public static void main(String[] args) {
        Server.create().start();
    }
}
```

#### **f. Ejecutar Helidon ME**
Compila y ejecuta el proyecto:
```bash
mvn clean package
java -jar target/helidon-me-example.jar
```

### **4. Cliente Jakarta EE**

#### **a. Código del Cliente**
```java
package com.example.client;

import jakarta.ws.rs.client.ClientBuilder;
import jakarta.ws.rs.core.Response;

public class RestClient {
    public static void main(String[] args) {
        String token = "your-jwt-token"; // Obtén el token de Keycloak

        Response response = ClientBuilder.newClient()
                .target("http://localhost:8080/api/admin")
                .request()
                .header("Authorization", "Bearer " + token)
                .get();

        System.out.println(response.readEntity(String.class));
    }
}
```

### **5. Resumen**
- **Payara Micro**: Usa `keycloak.json` y anotaciones como `@RolesAllowed`.
- **Helidon ME**: Configura OIDC en `application.yaml` y usa anotaciones como `@RolesAllowed`.
- **Cliente Jakarta EE**: Envía tokens JWT en las cabeceras HTTP para acceder a los endpoints protegidos.
