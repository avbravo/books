Agrega una aplicación cliente que usa Jakarta faces para comunicarse con otra aplicación que usa eclipse micropofile y está se comunica con keycloack muéstrame el ejemplo completo 

A continuación, te proporciono un ejemplo completo de cómo integrar una **aplicación cliente** creada con **Jakarta Faces** que se comunica con una **aplicación backend** basada en **Eclipse MicroProfile**. La aplicación backend utiliza **Keycloak** para la autenticación y autorización.

---

### **1. Configuración General**

#### **a. Keycloak**
1. Inicia Keycloak en `http://localhost:8080/auth`.
2. Crea un realm llamado `microprofile-realm`.
3. Registra dos clientes:
   - `backend-client` (para el backend MicroProfile).
   - `frontend-client` (para la aplicación Jakarta Faces).
4. Define roles como `admin` y `user` en Keycloak.
5. Habilita el mapeo de roles en los tokens JWT.

---

### **2. Backend con Eclipse MicroProfile**

#### **a. Estructura del Proyecto**
```
microprofile-backend/
├── src/main/java/com/example/backend/
│   ├── MyResource.java
│   └── ApplicationConfig.java
├── src/main/resources/
│   └── META-INF/microprofile-config.properties
├── pom.xml
└── README.md
```

#### **b. Archivo `pom.xml`**
```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>microprofile-backend</artifactId>
    <version>1.0-SNAPSHOT</version>

    <dependencies>
        <dependency>
            <groupId>org.eclipse.microprofile</groupId>
            <artifactId>microprofile</artifactId>
            <version>4.0</version>
            <type>pom</type>
        </dependency>
        <dependency>
            <groupId>io.helidon.security.providers</groupId>
            <artifactId>helidon-security-providers-oidc</artifactId>
            <version>3.0.0</version>
        </dependency>
    </dependencies>

    <build>
        <finalName>microprofile-backend</finalName>
    </build>
</project>
```

#### **c. Archivo `microprofile-config.properties`**
Coloca este archivo en `src/main/resources/META-INF/microprofile-config.properties`:
```properties
mp.jwt.verify.publickey.location=http://localhost:8080/auth/realms/microprofile-realm/protocol/openid-connect/certs
mp.jwt.verify.issuer=http://localhost:8080/auth/realms/microprofile-realm
```

#### **d. Código del Servicio REST**
```java
package com.example.backend;

import org.eclipse.microprofile.jwt.JsonWebToken;
import jakarta.annotation.security.RolesAllowed;
import jakarta.inject.Inject;
import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.core.MediaType;

@Path("/api")
public class MyResource {

    @Inject
    JsonWebToken jwt;

    @GET
    @Path("/admin")
    @RolesAllowed("admin")
    @Produces(MediaType.TEXT_PLAIN)
    public String adminEndpoint() {
        return "Admin access granted! User: " + jwt.getName();
    }

    @GET
    @Path("/user")
    @RolesAllowed("user")
    @Produces(MediaType.TEXT_PLAIN)
    public String userEndpoint() {
        return "User access granted! User: " + jwt.getName();
    }
}
```

#### **e. Archivo `ApplicationConfig.java`**
```java
package com.example.backend;

import jakarta.ws.rs.ApplicationPath;
import jakarta.ws.rs.core.Application;

@ApplicationPath("/api")
public class ApplicationConfig extends Application {
}
```

#### **f. Ejecutar el Backend**
Compila y ejecuta el proyecto:
```bash
mvn clean package
java -jar target/microprofile-backend.jar
```

### **3. Aplicación Cliente con Jakarta Faces**

#### **a. Estructura del Proyecto**
```
jakarta-faces-client/
├── src/main/java/com/example/frontend/
│   └── RestClient.java
├── src/main/webapp/
│   ├── index.xhtml
│   └── WEB-INF/web.xml
├── pom.xml
└── README.md
```

#### **b. Archivo `pom.xml`**
```xml
<project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <groupId>com.example</groupId>
    <artifactId>jakarta-faces-client</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>war</packaging>

    <dependencies>
        <dependency>
            <groupId>jakarta.platform</groupId>
            <artifactId>jakarta.jakartaee-api</artifactId>
            <version>9.1.0</version>
            <scope>provided</scope>
        </dependency>
    </dependencies>

    <build>
        <finalName>jakarta-faces-client</finalName>
    </build>
</project>
```

#### **c. Archivo `web.xml`**
```xml
<web-app xmlns="http://xmlns.jcp.org/xml/ns/javaee" version="3.1">
    <servlet>
        <servlet-name>Faces Servlet</servlet-name>
        <servlet-class>jakarta.faces.webapp.FacesServlet</servlet-class>
        <load-on-startup>1</load-on-startup>
    </servlet>
    <servlet-mapping>
        <servlet-name>Faces Servlet</servlet-name>
        <url-pattern>*.xhtml</url-pattern>
    </servlet-mapping>
</web-app>
```

#### **d. Código del Cliente REST**
```java
package com.example.frontend;

import jakarta.enterprise.context.RequestScoped;
import jakarta.ws.rs.client.ClientBuilder;
import jakarta.ws.rs.core.Response;

@RequestScoped
public class RestClient {

    private String token = "your-jwt-token"; // Obtén el token de Keycloak

    public String callBackend(String endpoint) {
        Response response = ClientBuilder.newClient()
                .target("http://localhost:8080/api/" + endpoint)
                .request()
                .header("Authorization", "Bearer " + token)
                .get();

        return response.readEntity(String.class);
    }
}
```

#### **e. Vista con Jakarta Faces (`index.xhtml`)**
```xml
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml"
      xmlns:h="http://xmlns.jcp.org/jsf/html">
<h:head>
    <title>Jakarta Faces Client</title>
</h:head>
<h:body>
    <h:form>
        <h:outputText value="Backend Response:" />
        <h:commandButton value="Call Admin Endpoint" action="#{restClient.callAdmin}" />
        <h:commandButton value="Call User Endpoint" action="#{restClient.callUser}" />

        <h:outputText value="#{restClient.response}" />
    </h:form>
</h:body>
</html>
```

#### **f. Managed Bean**
```java
package com.example.frontend;

import jakarta.faces.bean.ManagedBean;
import jakarta.faces.bean.ViewScoped;

@ManagedBean
@ViewScoped
public class RestClientBean {

    private String response;

    public String getResponse() {
        return response;
    }

    public void callAdmin() {
        RestClient client = new RestClient();
        response = client.callBackend("admin");
    }

    public void callUser() {
        RestClient client = new RestClient();
        response = client.callBackend("user");
    }
}
```

#### **g. Ejecutar el Cliente**
Compila y despliega el proyecto en un servidor Jakarta EE como Payara o WildFly:
```bash
mvn clean package
asadmin deploy target/jakarta-faces-client.war
```

---

### **4. Flujo Completo**
1. El usuario inicia sesión en Keycloak desde la aplicación Jakarta Faces.
2. La aplicación obtiene un token JWT de Keycloak.
3. El token se envía al backend MicroProfile en las cabeceras HTTP.
4. El backend valida el token y verifica los roles antes de responder.

Este ejemplo es completamente funcional y muestra cómo integrar Jakarta Faces con Eclipse MicroProfile y Keycloak. Si necesitas más detalles o tienes preguntas adicionales, no dudes en preguntar. 😊
