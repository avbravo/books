# PROGRESO# Contexto y Objetivo
En el proyecto **JettraStore**, se ha implementado un mecanismo de distribución de bases de datos y registros desde el nodo **PRIMARIO** hacia los nodos **secundarios** utilizando el algoritmo de consenso **Raft**. Sin embargo, se ha detectado un fallo crítico: cuando se crea una nueva base de datos en el nodo primario, dicha operación (junto con sus registros e índices asociados) no se está replicando en los dos nodos secundarios. Esta funcionalidad es fundamental para la persistencia distribuida y el funcionamiento correcto de JettraStore.

# Requisitos Técnicos para la Corrección
1. **Inspección del Flujo de Creación de Bases de Datos:**
   - Revisar el manejador de comandos o la API en el nodo primario encargada de procesar la creación de bases de datos.
   - Asegurar que la orden de creación sea empaquetada como una entrada de registro (log entry) de Raft y propagada mediante el mecanismo de replicación del líder.

2. **Propagación de Registros e Índices:**
   - Verificar que, una vez que el log de creación de la base de datos sea confirmado (committed) por la mayoría del cluster Raft, se ejecute la máquina de estados (state machine) en cada nodo secundario para materializar físicamente la base de datos, sus estructuras de almacenamiento (como páginas y ranuras/slots) y sus respectivos índices.

3. **Manejo de Consistencia y Estado:**
   - Asegurar que los nodos secundarios inicialicen correctamente sus metadatos internos al recibir la orden replicada, evitando condiciones de carrera o fallos silenciosos si la ruta de archivos de la base de datos no existe en el disco del secundario.

# Tareas para Antigravity IDE

- Proveer los cambios de código necesarios y las pruebas unitarias/de integración para validar que un comando ejecutado en el nodo primario se replique de manera síncrona/asíncrona correctamente en los nodos secundarios del cluster.

# Prompt para GitHub Copilot: Creación de la Extensión "JettraVSCPlugin" para VS Code

Actúa como un arquitecto de software experto en el desarrollo de extensiones para Visual Studio Code (usando TypeScript y la API de VS Code) y en sistemas distribuidos basados en Java/Jettra. 

Tu objetivo es diseñar e implementar la estructura inicial y la lógica principal del plugin de VS Code llamado **`JettraVSCPlugin`**. Este plugin debe replicar, adaptar y ofrecer las capacidades administrativas de **JettraStorePolice3D** directamente dentro de la interfaz de Visual Studio Code.

---

## 1. Especificaciones Funcionales del Plugin

El plugin debe gestionar de forma visual e interactiva los siguientes elementos provistos por el ecosistema **JettraStore**:

1. **Gestión de Conexiones y Nodos (Basado en `jettra.config`):**
   - Leer la topología de nodos y configuraciones de red directamente desde un archivo `jettra.config` del workspace o mediante configuración de la extensión.
   - Permitir conectarse/desconectarse a los diferentes nodos del cluster (ej. `local_master`, réplicas, nodos virtuales `127.0.0.2`, `127.0.0.3`, etc.).
   - Incluir un comando y una vista de árbol (`TreeView`) en la barra lateral de VS Code ("Jettra Explorer") que muestre el estado de salud del cluster (equivalente a `cluster live`).

2. **Administración de Bases de Datos y Engines:**
   - Visualizar el listado de bases de datos activas en el cluster administrado por JettraStore.
   - Permitir crear, inspeccionar y eliminar bases de datos.
   - Administrar los motores de almacenamiento (**Engines**, ej. slotted-page layouts, estructuras off-heap, etc.) asociados a cada base de datos.

3. **Gestión de Índices y Registros:**
   - Explorar los índices vectoriales o estructurados configurados en los nodos.
   - Consultar, insertar o eliminar registros de manera visual (interfaz tabular o paneles interactivos estilo visor de datos).

4. **Gestión de Usuarios y Seguridad:**
   - Administrar credenciales, roles y permisos de usuarios (ej. usuario `admin` por defecto y otros configurados en el sistema).

---

## 2. Estructura Técnica y Arquitectura del Proyecto

Genera el código en TypeScript siguiendo la estructura estándar de una extensión de VS Code:

- **`package.json`**: Declaración de comandos, contribuciones (`contributes.viewsContainers`, `contributes.views`, `contributes.commands`), y configuración de ajustes (`configuration`).
- **`src/extension.ts`**: Punto de entrada que inicializa las activaciones, registra los comandos (`jettra.connect`, `jettra.clusterLive`, `jettra.refreshExplorer`, etc.) y vincula los proveedores de datos.
- **`src/providers/JettraTreeDataProvider.ts`**: Proveedor del árbol de elementos para la barra lateral (Nodos -> Bases de Datos -> Engines -> Índices/Registros).
- **`src/services/JettraClientService.ts`**: Servicio de comunicación (gRPC / HTTP / sockets según aplique al protocolo de JettraStore) para interactuar con los nodos distribuidos y procesar el comando `cluster live`.
