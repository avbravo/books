- [] Verificar que cuando se ejecute jettrastore almacene los datos en la configuracion establecida
en el archivo cluster.config en el parametro cluster.node.1.storage.path o cluster.node.2.storage.path o cluster.node.3.storage.path
o incluso mas nodos si se llegan a definir.
Recuerda que el archivo microprofile-config.properties en la propiedad cluster.node.id=
identifica el cluster a usar 
cluster.node.id=node-01
o
cluster.node.id=node-02
o
cluster.node.id=node-03

y esto indica que debe buscar en el archivo cluster.config en indicar cual usar

cluster.node.1.id = node-01
usaria
cluster.node.1.storage.path = ~/jettra/data-1

si es
cluster.node.1.id = node-02
cluster.node.1.storage.path = ~/jettra/data-2

Para almacenar la data de cada nodo recuerde que unos son primarios y otros secundarios

Estos se ejecutan desde el archivo start-node.sh que puede tener el indicativo de la informacion del nodo
NODE_ID="node-03"
NODE_ROLE="SECONDARY"

java --enable-preview \
     --enable-native-access=ALL-UNNAMED \
     -XX:+UnlockExperimentalVMOptions \
     -XX:+UseCompactObjectHeaders \
     -XX:+UseZGC \
     -Xms2g -Xmx6g \
     -Djettra.node.id="${NODE_ID}" \
     -Djettra.node.role="${NODE_ROLE}" \
     -Dcluster.config.path=config/cluster.config \
     -Dmicroprofile.config.file=config/microprofile-config.properties \
     -jar JettraStore-1.0-SNAPSHOT-uber.jar


Recuede que estos nodos tambien se pueden ejecutar desde Docker compose, y ellos tienen su propia configuracion

lo que se desea es que cada nodo guarde los datos en el path especificado para cada nodo.
