# 01.04.04 Query Rules
Este documento muestra las reglas que se usan para la generación de la implementación.
Este proceso lo realiza de manera automatia el Framework.
## Reglas:
1. Los supplier se deben generar en el mismo paquete que los Entity. Mediante un processor especifico para los Entity,
2. El Framework toma el paquete de entity para inyectar el Supplier.
3. Se debe configurar la(s) base de datos en el archivo microprofile-config.properties
4. Si no se especifica en la anotación o se coloca vacia en @Repository (database=""), se tomara como referencia mongodb.database definido en el archivo microprofile.config.properties
5. Si se usan varias bases de datos, defina en microprofile-config.properties la base de datos por ejemplo: mongodb.database1 ="autentificación", y utilice en el Repositorio   @Repository(database ="{mongodb.database1}") . Incluyalo dentro de {} para denotar que es una propiedad del archivo microprofile-config.properties.
6. No se permite más de 4 parametros en los métodos que usan @Query
7. Verifica el nombre de los parámetros @ coincidan con los parámetros declarados en el método
8. Verifica que no se repitan los nombres de atributos ni parámetros declarados.
9. Verifica que nos nombres de identificadores coincidan con los nombres de parámetros declarados en el método. Esto garantiza la correcta escritura de métodos.
10. .skip. solo se usa con .limit. para paginación o solo si no hay más condiciones.

## Reglas para Generar Query
### where()
Se cuenta con el método
```java
    @Query()
    public List<Oceano> findAll();
```
Condiciones:  
1. El where ="" no debe contener parametros.
2. Verificar si where = "" y tiene parametros es incorrecto el where
3. Si where != "" y no tiene parametros el Query no es valido
4. Si tiene valores en where deben coincidir con la lista de parametros
5. Validar que los parametros dentro de where contengan = y @
6. Validar que exista una variable despues de @avbravo
7. Validar que exista una variable antes de =
8. Validar que adicional al simbolo = puede existir != < > >= =< between entre otros

## Analizar el uso de  Paginación
Para Paginación tenemos algunas restricciones:
- Usar el parametro Pagination en el método
- En el where usar .limit. .skip. cuando hay más de una condición
- Usar solo .skip. cuando solo hay una condición

Ejemplo 
```java
    @Query(where="pagination .skip. @pagination")
    public List<Oceano> findAllPagination(Pagination pagination);
    
   @Query(where = "oceano .eq. @oceano .limit. pagination .skip. @pagination .order. sort .eq. @sort", activatePagination = ActivatePagination.ON, activateSort = ActivateSort.ON)
    public List<Oceano> findByOceanoPagination(String oceano, Pagination pagination, Document sort);

```
