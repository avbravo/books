## RF-16: Aislamiento y limpieza automática de bases de datos en tests de `JettraStorageContainers`

### Contexto y objetivo
Al compilar o ejecutar las suites de pruebas en los proyectos de `JettraStorageContainers`, se están creando bases de datos temporales que quedan persistidas o mezcladas con el entorno de producción. Necesito garantizar el aislamiento total y la limpieza automática de estas bases de datos.

### Tareas requeridas
1. **Localización:** Audita todos los proyectos, tests, fixtures y helpers dentro de `JettraStorageContainers` que creen, inicialicen o se conecten a bases de datos.
2. **Aislamiento de entorno:** Asegura que los tests utilicen siempre instancias, contenedores, rutas o prefijos exclusivos de prueba (por ejemplo, `test_*` o bases efímeras en memoria/contenedores aislados), garantizando que nunca lean, escriban ni apunten a configuración o datos de producción.
3. **Limpieza garantizada (Teardown):** Implementa mecanismos de eliminación automática (`Dispose`, `IAsyncLifetime`, `[TearDown]`, `@AfterEach`, bloques `finally`, etc., según el framework) para borrar todas las bases de datos y artefactos generados al finalizar cada test o suite, **incluso si la prueba falla o se cancela**.
4. **Limpieza de residuos actuales:** Si existen bases de datos residuales de pruebas previas en el workspace o configuración local, identifícalas y elimínalas.

### Criterios de aceptación y verificación
* Ejecuta la compilación y los tests afectados para comprobar que pasan correctamente.
* Verifica tras la ejecución que no queda ninguna base de datos de prueba persistida.
* En el resumen final, lista los archivos, fixtures o configuraciones modificadas y explica brevemente cómo se garantiza la limpieza ante fallos.
