## Stack y Reglas Arquitectónicas Obligatorias
- **Lenguaje y Runtime:** Java 25+ (Virtual Threads, Records, Pattern Matching).
- **UI Web:** Exclusivamente componentes Java puros con `JettraFlux` (prohibido inyectar HTML/CSS/JS crudo en la lógica de negocio y prohibido usar jQuery; usar Vanilla JS únicamente si es estrictamente necesario en el cliente).
- **Pruebas:** Implementar todas las pruebas unitarias y de integración exclusivamente con `JettraTest` (prohibido usar JUnit).

## 1. Especificación Técnica de `JettraId`
Implementar el identificador interno único y clave primaria por defecto **`JettraId`** (16 bytes / representación canónica hexadecimal en minúsculas de 32 caracteres) con la siguiente estructura binaria en orden big-endian:

1. **Timestamp (4 bytes):** Segundos transcurridos desde la época Unix (`1970-01-01T00:00:00Z`), permitiendo ordenación aproximada por orden de creación y extracción de la marca de tiempo (`createdAt()`).
2. **Identificador de Proceso / Máquina (5 bytes):** Código aleatorio de 40 bits generado por instancia/JVM al arrancar el proceso para evitar colisiones entre nodos o procesos concurrentes.
3. **Código de Base de Datos y Bucket (4 bytes):** Hash determinista de 32 bits calculado a partir de `databaseName + ":" + bucketName` (ej. MurmurHash3 / FNV-1a de 32 bits) para identificar y aislar el espacio de claves de cada base de datos y bucket.
4. **Contador Incremental de Proceso (3 bytes):** Contador atómico incremental de 24 bits (`AtomicInteger` enmascarado con `0xFFFFFF`, inicializado con semilla aleatoria) por proceso para garantizar unicidad en inserciones simultáneas dentro del mismo segundo.

Proveer métodos de generación (`JettraId.generate(String databaseName, String bucketName)`), parseo/validación (`JettraId.fromHex(String hex)`), serialización a `byte[]` y `String`, y extracción de metadatos (timestamp, proceso, hash DB/bucket y secuencia).

## 2. Requerimientos por Módulo

### A. `JettraStore` (Motor Core y Almacenamiento `.jettra`)
- **Generación e integridad automática:** En toda operación de inserción/creación de registros (`insert`, `put`, `save`), si el registro entrante no incluye un identificador o este viene nulo/vacío, `JettraStore` debe generar automáticamente un `JettraId` utilizando el nombre de la base de datos y el bucket destino antes de persistir el registro en páginas `.jettra` o memoria Off-Heap.
- **Soporte de IDs personalizados:** Si el registro ya incluye un identificador válido provisto por el usuario o cliente, `JettraStore` debe respetarlo y verificar la unicidad dentro del bucket, rechazando duplicados con una excepción clara de integridad de clave primaria.
- **Indexación y retorno:** Asegurar que el `JettraId` generado quede almacenado dentro del registro, registrado en el índice primario del bucket y devuelto al invocador.

### B. `JettraStoreDriver`
- **Generación en cliente:** Al preparar o enviar operaciones de creación de registros, si el objeto/documento/record no tiene un identificador asignado, `JettraStoreDriver` debe generar automáticamente el `JettraId` correspondiente al `database` y `bucket` destino (manteniendo también compatibilidad con el fallback del servidor `JettraStore`).
- **Soportar sobrescritura:** Permitir que el desarrollador envíe un ID personalizado cuando lo requiera y exponer el `JettraId` asignado en el resultado de la operación de inserción.

### C. `JettraStoreShell`
- **Generación automática en comandos de creación:** Al ejecutar comandos para crear/insertar registros desde la consola interactiva sin especificar un identificador explícito, `JettraStoreShell` debe generar automáticamente el `JettraId`, enviarlo en la operación y mostrar en la salida de consola el `JettraId` asignado al nuevo registro.
- **ID manual:** Permitir especificar un ID personalizado como parámetro opcional en el comando de inserción.

### D. `JettraStoreExplorer` (`/explorer` con `JettraFlux`)
- En la página `/explorer`, al hacer clic en **`+ Nuevo Registro (Create)`**, al abrirse el diálogo **`➕ Crear Nuevo Registro en [ • Motor: ... • Estructura: ... ]`**:
  1. **Prellenado automático:** Generar automáticamente un `JettraId` (con la base de datos y el bucket/estructura activos) y mostrarlo prellenado en el campo **`Identificador Único (ID / Clave Primaria)`**.
  2. **Reemplazo libre por el usuario:** Permitir que el usuario edite o sustituya ese `JettraId` por cualquier identificador personalizado antes de guardar. Incluir también un botón de acción rápida para regenerar un nuevo `JettraId` si el usuario desea restablecerlo.
  3. **Descripción no obligatoria:** El campo de descripción del identificador no debe ser obligatorio (`required = false`), permitiendo guardar el registro aunque dicho campo quede vacío.
  4. **Validación y feedback:** Si el usuario deja vacío el campo de ID, el sistema deberá asignar automáticamente un `JettraId` para mantener la integridad. Si el ID ingresado ya existe en la estructura/bucket, mostrar una notificación de error clara sin cerrar el diálogo ni perder los datos capturados.
