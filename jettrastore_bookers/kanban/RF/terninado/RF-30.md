# RF-30
# Role & Authority
Actúa como un arquitecto de software senior especialista en Java 25+, servidores HTTP embebidos, redes Linux/Docker y el ecosistema `io.jettra` (`JettraStoreExplorer`, `JettraFlux`, `JettraTest`). No utilices Helidon ni JUnit; estandariza pruebas automatizadas con `JettraTest` (`JettraTestRunner`).

# Task (`Action-1`)
Diagnosticar y corregir el fallo de accesibilidad remota en **JettraStoreExplorer** (puerto `8085`): actualmente responde en `localhost:8085` / `127.0.0.1:8085`, pero al solicitar `http://192.168.60.243:8085` desde el navegador devuelve `ERR_CONNECTION_REFUSED` ("La página 192.168.60.243 ha rechazado la conexión").

# Technical Requirements & Constraints
1. **Bind Address Configurable (`0.0.0.0` por defecto):** Revisar cómo inicializa su socket/servidor HTTP `JettraStoreExplorer`. Asegurar que el host de enlace no esté fijado en `localhost` o `127.0.0.1` y que acepte conexiones en todas las interfaces (`0.0.0.0`) o mediante propiedad/variable de configuración (`host` / `bindAddress`, con fallback a `0.0.0.0` y puerto `8085`).
2. **Entorno de Ejecución (Host Ubuntu 26.04 / Docker):** Verificar si el proceso corre directamente en el host o dentro de un contenedor Docker:
   - Si corre en Docker / Docker Compose, validar la publicación de puertos (`0.0.0.0:8085:8085` o `192.168.60.243:8085:8085`) y el enlace interno del servidor a `0.0.0.0` dentro del contenedor.
   - Si corre en el host Ubuntu, revisar reglas de `ufw` / `iptables` y confirmar el estado de escucha con `ss -tulpn | grep 8085`.
3. **Resiliencia y CORS/Host Headers:** Evitar rechazos por validación estricta de cabecera `Host` cuando se accede por IP LAN (`192.168.60.243:8085`).
4. **Pruebas con JettraTest:** Agregar pruebas unitarias o de integración usando `JettraTest` (`JettraTestRunner`) que validen la resolución del host/puerto de enlace y la configuración por defecto (`0.0.0.0` y `8085`).

# Deliverables
1. Diagnóstico conciso de las causas raíz (`127.0.0.1` bind, Docker port mapping o firewall).
2. Cambios exactos en código y configuración de **JettraStoreExplorer** para escuchar en `0.0.0.0:8085` de forma configurable.
3. Comandos de verificación en Ubuntu/Docker (`ss`, `curl -i http://192.168.60.243:8085`, revisión de logs).
4. Caso de prueba con `JettraTest` (`JettraTestRunner`).
