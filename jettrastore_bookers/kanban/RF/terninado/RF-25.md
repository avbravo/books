# RF-25: Construcción y publicación de la imagen Docker de JettraStore en Docker Hub

## Rol y autoridad
Actúa como arquitecto de sistemas distribuidos y especialista en DevOps/contenedores para el ecosistema **Jettra** (`io.jettra`) sobre **Java 25+**, **Ubuntu 26.04** y **Docker**.

## Tarea
Diseñar, optimizar y ejecutar el flujo completo para construir, probar localmente y publicar la imagen oficial de **JettraStore** en **Docker Hub**, asegurando compatibilidad con despliegues de un solo nodo y clústeres multi-nodo (Raft/Gossip) y documentando el procedimiento.

## Requisitos técnicos y restricciones
- **Java y runtime:** Compilar y ejecutar sobre **Java 25+** (incluyendo flags de JVM relevantes para el motor como Generational ZGC y `-XX:+UseCompactObjectHeaders` cuando aplique).
- **Imagen base ligera:** Optimizar el `Dockerfile` para bajo consumo de recursos (p. ej., imagen base ligera tipo Alpine/Alpaquita Linux o JRE/jlink mínimo) evitando capas innecesarias o artefactos de compilación en la imagen final.
- **Configuración y red:** Soportar parametrización por variables de entorno y montaje de configuración (`cluster.config` / puertos / rutas de almacenamiento `.jettra`) para ejecutar tanto en modo standalone como en clústeres locales o multi-nodo vía Docker Compose.
- **Pruebas y validación:** Validar la construcción y el arranque del contenedor usando **JettraTest** / pruebas de integración (verificando salud del nodo, persistencia/replicación básica y limpieza de contenedores de prueba).
- **Publicación en Docker Hub:** Etiquetar la imagen con versión semántica y `latest` (bajo el namespace/repositorio configurado para Docker Hub) y subirla mediante `docker push`, dejando scripts o comandos reproducibles.
- **Documentación:** Actualizar `JettraStore/guide/book.md` con la guía de construcción, variables de entorno, ejecución single-node / multi-node y publicación en Docker Hub.
- **Exclusiones:** No utilices Helidon ni JUnit en ningún componente o prueba asociada.

## Entregables
1. `Dockerfile` optimizado para `JettraStore` (y archivo `.dockerignore` si aplica).
2. Configuración/ejemplo de ejecución con `docker compose` (single-node y/o multi-node) y script o comandos reproducibles de build, test y `docker push` a Docker Hub.
3. Suite de verificación con **JettraTest** que valide el ciclo del servicio/nodo en entorno contenedorizado.
4. Actualización en `JettraStore/guide/book.md` documentando el flujo completo de RF-25.
