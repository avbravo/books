# RF-14
# Contexto y Problema
Al ejecutar `JettraStoreExampleSE`, se crea correctamente la base de datos `examplesedb` con `Bucket`s, índices y registros (verificado porque `JettraStoreShell` muestra los datos). Sin embargo, al abrir `JettraStoreExplorer` en la ruta `/explorer`, no se muestran ni los `Bucket`s creados ni sus registros para `examplesedb`.

# Objetivo
Diagnosticar y corregir la integración de `JettraStoreExplorer` (`/explorer`) con `JettraStore` / `JettraStoreDriver` para que la base de datos `examplesedb` refleje exactamente el mismo estado de `Bucket`s, índices y registros que `JettraStoreShell`, manteniendo la arquitectura Java 25+ y `JettraFlux` del ecosistema.

# Alcance y Tareas Requeridas
1. **Comparar flujo de datos (`Shell` vs. `Explorer` sobre `examplesedb`):**
   - Inspeccionar cómo `JettraStoreShell` resuelve y consulta la base de datos `examplesedb`, el motor (`DOCUMENT`, etc.), los `Bucket`s (migrados desde `COLLECTION`), los índices y los registros.
   - Comparar con los endpoints, parámetros, serialización/deserialización (`JettraJSON` / DTOs / records) y llamadas de red/driver usadas en `JettraStoreExplorer` al cargar `/explorer` para `examplesedb`.

2. **Corregir carga y renderizado en `/explorer` (`JettraStoreExplorer`):**
   - Asegurar que el árbol jerárquico izquierdo (`Base de Datos -> Motor -> Bucket`) cargue `examplesedb` y expanda los `Bucket`s persistidos por `JettraStoreExampleSE` sin filtrar erróneamente por base de datos activa, motor o estado vacío.
   - Asegurar que al seleccionar un `Bucket` dentro de `examplesedb` se actualice su cabecera y la `DataTable` de registros muestre todos los documentos/registros creados (incluyendo columnas como `ID`, `MOTOR`, `BUCKET`, `RESUMEN`, `VERSION`, `FECHA MUTACION`, `ACCIONES`, según corresponda).
   - Verificar que las vistas de estructura e índices del `Bucket` en `examplesedb` reflejen los índices y esquemas creados desde `JettraStoreExampleSE`.

3. **Manejo de errores y sincronización de estado:**
   - Eliminar silenciamiento de errores en controladores/servicios de `/explorer` (registrar causa y mostrar mensaje claro si falla la consulta al servidor o driver).
   - Garantizar refresco de datos al seleccionar `examplesedb` o cambiar de `Bucket`, así como compatibilidad con `JettraId` y metadatos de versión/mutación.

4. **Pruebas y Documentación:**
   - Añadir pruebas con `JettraTest` cubriendo la lectura de `Bucket`s, índices y registros en `examplesedb` en un escenario equivalente a `JettraStoreExampleSE`.
   - Actualizar `JettraStoreExplorer/guide/book.md` documentando el flujo de consulta de `/explorer` sobre `examplesedb` y los puntos clave de diagnóstico si `Shell` muestra datos y `Explorer` no.

# Criterios de Aceptación
- Tras ejecutar `JettraStoreExampleSE`, abrir `/explorer` en `JettraStoreExplorer` muestra la base de datos `examplesedb`, los `Bucket`s, sus índices y todos los registros creados de forma consistente con `JettraStoreShell`.
- El proyecto compila en Java 25+ y las pruebas en `JettraTest` pasan sin regresiones.
