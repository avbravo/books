    # RF-28

    # Validación de nodos activos en JettraStoreShell antes de ejecutar comandos de base de datos

    ## Rol y autoridad
    Actúa como arquitecto de software senior especialista en **Java 25+**, interfaces CLI interactivas y sistemas distribuidos (**Raft/Gossip**) para el ecosistema **Jettra** (`io.jettra`).

    ## Tarea
    Modificar **JettraStoreShell** para bloquear la ejecución de cualquier comando u operación relacionada con bases de datos cuando no exista al menos un nodo activo (`ONLINE`) en el clúster, permitiendo dichas operaciones únicamente cuando haya 1 o más nodos disponibles.

    ## Requisitos técnicos y restricciones
    - **Verificación de estado del clúster:** Antes de despachar cualquier comando de operación de base de datos (como crear/eliminar/seleccionar bases de datos, gestionar motores, buckets, estructuras, índices, consultas o operaciones CRUD de registros), verificar en tiempo real mediante `JettraStoreDriver` (o el gestor de estado de nodos del shell) si existe al menos un nodo activo.
    - **Comandos permitidos sin nodos activos:** Mantener habilitados los comandos locales, administrativos o de diagnóstico que no operan sobre datos (por ejemplo: `help`, `exit`/`quit`, `clear`, `show nodes`, `start node`, `add node`, `connect` o configuración de conexión), de modo que el usuario pueda inspeccionar el clúster o levantar un nodo desde el propio shell.
    - **Mensaje de error claro:** Si todos los nodos están inactivos/caídos o no hay conexión con ningún nodo activo, rechazar el comando de base de datos inmediatamente sin provocar excepciones no controladas ni timeouts largos, mostrando un mensaje claro en consola (por ejemplo: `⚠️ Error: No hay ningún nodo activo en el clúster. Inicie o conecte al menos un nodo antes de ejecutar operaciones de base de datos.`).
    - **Stack y exclusiones:** Desarrollar sobre **Java 25+** siguiendo la arquitectura existente de `JettraStoreShell` y `JettraStoreDriver`. No utilizar Helidon ni JUnit en ningún componente o prueba.
    - **Pruebas y documentación:**
      - Agregar pruebas automatizadas con **JettraTest** que cubran ambos escenarios: rechazo de comandos de BD con `0` nodos activos y ejecución exitosa con `≥ 1` nodo activo.
      - Documentar este comportamiento en `JettraStoreShell/guide/book.md`.

    ## Entregables
    1. Código actualizado en `JettraStoreShell` con la validación centralizada de nodos activos para comandos de base de datos.
    2. Suite de pruebas unitarias/integración con **JettraTest** validando el bloqueo sin nodos activos y la ejecución con nodos activos.
    3. Actualización en `JettraStoreShell/guide/book.md` describiendo la restricción y el mensaje de validación.
