# RF-20: Pruebas de estrés y reporte de tolerancia de base de datos con JettraStoreMeter

## Objetivo
Preparar un entorno aislado en contenedor llamado `jettrastoretestcontainer` para ejecutar pruebas de estrés con **JettraStoreMeter** y generar un reporte de tolerancia que respalde los límites y el soporte de la base de datos.

## Alcance y componentes
- **Contenedor de pruebas:** `jettrastoretestcontainer` (con el proyecto `JettraStoreMeter` desplegado/copiado en su interior).
- **Herramienta de carga/estrés:** `JettraStoreMeter`.
- **Entregable final:** Reporte de tolerancia y rendimiento de la base de datos.

## Instrucciones

### 1. Entorno en contenedor (`jettrastoretestcontainer`)
- Crea y configura el contenedor `jettrastoretestcontainer`.
- Traslada/monta el proyecto `JettraStoreMeter` dentro del contenedor y verifica que pueda ejecutarse apuntando a la base de datos objetivo.
- Asegúrate de aislar correctamente el entorno de pruebas respecto a datos o configuraciones de producción.

### 2. Ajuste de `JettraStoreMeter` para pruebas de estrés
- Adapta `JettraStoreMeter` para soportar ejecuciones parametrizadas de volumen de registros y concurrencia de usuarios.
- Registra métricas clave durante cada ejecución:
  - Tiempo total de ejecución y latencia (promedio, p95, p99 o máximos según disponibilidad).
  - Throughput / operaciones por segundo.
  - Tasa de errores, timeouts, bloqueos o caídas de conexión.
  - Estado y estabilidad de la base de datos ante cada carga.

### 3. Escenarios de prueba

#### Volúmenes de registros
Ejecutar pruebas con los siguientes volúmenes:
- `10,000`
- `100,000`
- `1,000,000`
- `1,500,000`
- `25,000,000`
- `35,000,000`
- `50,000,000`

#### Concurrencia de usuarios
Ejecutar pruebas con los siguientes niveles de usuarios:
- `1`, `10`, `20`, `50`, `75`, `100`
- `1,000`, `2,000`, `5,000`, `10,000`
- `150,000`, `1,000,000`, `2,300,000` *(revisar si `150000`, `1000000` y `2300000` son valores exactos deseados o si requieren ejecución escalonada / ajuste de recursos del host)*

### 4. Generación del reporte de tolerancia
- Al finalizar las pruebas, consolida los resultados en un reporte claro y estructurado.
- Indica en qué punto la base de datos mantiene un comportamiento estable, dónde empieza a degradarse y cuál es su límite de tolerancia observado.
- Incluye conclusiones que sirvan como evidencia técnica para definir o respaldar el soporte de la base de datos.

## Criterio de aceptación
- `jettrastoretestcontainer` está creado y ejecuta `JettraStoreMeter` sin fallos de entorno.
- `JettraStoreMeter` corre los escenarios definidos y captura métricas de rendimiento y errores.
- Se genera el reporte final de tolerancia con datos suficientes para sustentar el soporte de la base de datos.
