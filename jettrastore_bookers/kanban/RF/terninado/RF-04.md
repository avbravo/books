# RF-04
# Especificación funcional y de UI: Administración de Índices, Motores de Almacenamiento y Buckets en JettraStoreExplorer (`/database`)

## Contexto y stack tecnológico
- Proyecto: **JettraStoreExplorer** dentro del ecosistema **JettraStore** (Java 25+, UI reactiva con **JettraFlux**, pruebas unitarias e integración con **JettraTest** — sin JUnit).
- Vista objetivo: Página `/database` (y su documentación actualizada en `JettraStoreExplorer/guide/book.md`).

---

## 1. Diálogo "Administración de Índices en [nombre-base-de-datos]"
Al hacer clic en **Administrar Índices** desde la página `/database`:
1. Abrir el diálogo modal **Administración de Índices en [nombre-base-de-datos]**.
2. Mostrar el listado de **Engines** disponibles en la base de datos.
3. Dentro de cada **Engine**, listar los **Buckets** que pertenecen a ese Engine.
4. **Regla estricta de asignación:**
   - Un índice **nunca** se asigna directamente al Engine.
   - Todo índice se crea, consulta, edita o elimina **exclusivamente sobre un Bucket concreto** dentro de su Engine.
5. Para cada Bucket dentro de cada Engine, permitir:
   - Ver los índices existentes asociados a ese Bucket (nombre, campo(s), tipo/estrategia de índice incluyendo índices numéricos y auto-incrementales, estado).
   - **Añadir** un nuevo índice al Bucket seleccionado.
   - **Editar** o **eliminar** un índice existente del Bucket seleccionado.
   - Validar que los campos indexados sean coherentes con la estructura del Bucket (si tiene estructura definida) o se manejen de forma segura en Buckets sin estructura (`NONE` / esquema libre).

---

## 2. Diálogo "Motores de Almacenamiento y Buckets en [nombre-base-de-datos]"
Al hacer clic en **Administrar Motores** desde la página `/database`:
1. Abrir el diálogo modal **Motores de Almacenamiento y Buckets en [nombre-base-de-datos]**.
2. Mostrar el listado de **Engines** de almacenamiento y, dentro de cada Engine, sus **Buckets** asociados.
3. **Acciones sobre Buckets dentro de cada Engine:**
   - **Añadir bucket** dentro del Engine seleccionado.
   - **Editar bucket** existente (nombre/configuración/estructura según el modo del Bucket).
   - **Remover bucket** existente (con confirmación explícita y manejo de registros/índices asociados).
4. **Modo de estructura por Bucket y Engine:**
   - Dependiendo del tipo de **Engine** (por ejemplo: Document, Key-Value, Graph, Time-Series, Geospatial, Record, Vector, Column, Object), un Bucket puede configurarse **con estructura definida** o **sin estructura**.
   - **Bucket con estructura definida:** Todo registro insertado o actualizado dentro del Bucket debe validar y respetar estrictamente su estructura definida (rechazando registros no conformes con mensajes claros de validación).
   - **Bucket sin estructura:** Los registros pueden contener cualquier tipo de información / estructura libre según las capacidades del Engine.
5. **Definición de estructura mediante tabla:**
   - Cuando un Bucket tenga estructura definida, permitir gestionar sus campos mediante una tabla con las columnas exactas:
     `| nombre | tipo | rules | descripcion |`
   - **Columna `nombre`:** Nombre del atributo/campo.
   - **Columna `tipo`:** Debe soportar:
     - Tipos Java estándar (primitivos/wrappers, `String`, `Instant`, `LocalDate`, `UUID`, `BigDecimal`, etc.).
     - Nuevos objetos de dominio creados por el usuario (por ejemplo `record` o clases de usuario del proyecto).
     - Tipos genéricos de colección en forma de `List<>`, `Set<>`, `ArrayList<>` (incluyendo parametrización como `List<String>`, `Set<MiObjeto>`, `ArrayList<Integer>`, etc.).
   - **Columna `rules`:** Reglas de validación / restricciones del campo (integrables con **JettraRules** o expresiones de regla definidas para el campo).
   - **Columna `descripcion`:** Descripción funcional o técnica del campo.
   - Adaptar las opciones, sugerencias o validaciones de la estructura al tipo de **Engine** específico.

  - Asignación de índices únicamente a Buckets dentro de un Engine (y bloqueo de asignación directa al Engine).
