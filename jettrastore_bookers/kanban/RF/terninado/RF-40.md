# RF-40: Adaptación de Dockerfiles, Docker Compose y Documentación (`guide/book.md`) para `cluster.node.*` y `cluster.conf` en PRIMARY/SECONDARY

# Role & Authority
Actúa como un ingeniero principal de sistemas distribuidos y arquitectura Java 25+ especializado en **JettraStore**, contenedores Docker y documentación técnica bajo Spec-Driven Development (SDD).

# Task
Adaptar todos los `Dockerfile` y todos los archivos `docker-compose` del proyecto **JettraStore** (y su ecosistema en `jettrastorecontainers` si aplica) para exponer y pasar las nuevas propiedades de `microprofile-config.properties` mediante variables de entorno `ENV` y `environment:`, reflejando la regla vigente de que únicamente el nodo `PRIMARY` puede usar o cargar opcionalmente `cluster.conf` hacia `jettra.cluster_state_config_dir`, mientras que los nodos `SECONDARY` no utilizan `cluster.conf` y obtienen el estado desde el `PRIMARY`. Asimismo, actualizar `JettraStore/guide/book.md` incluyendo comandos `docker build`, configuración de `docker-compose` y el procedimiento para publicar imágenes en Docker Hub (`avbravo/jettrastore`).

## Context & Problem Description
La lógica de clúster en **JettraStore** ya está implementada y **no debe modificarse ni reimplementarse**:
- Solo el nodo `PRIMARY` puede especificar o no el archivo `cluster.conf`, cargándolo opcionalmente hacia el directorio configurado en `jettra.cluster_state_config_dir` (`microprofile-config.properties`).
- Los nodos `SECONDARY` no usan `cluster.conf`, ya que obtienen la configuración/estado del clúster desde el nodo `PRIMARY`.
- El archivo `microprofile-config.properties` ahora incorpora las siguientes propiedades:
  - `cluster.node.ip`
  - `cluster.node.grpc.port`
  - `cluster.node.rest.port`

Es necesario alinear los `Dockerfile`, todos los `docker-compose*.yml` y la documentación en `JettraStore/guide/book.md` para inyectar estas propiedades como variables de entorno en cada contenedor y documentar el ciclo completo de construcción, ejecución y publicación en Docker Hub.

## Technical Requirements & Constraints
1. **No reimplementar lógica de clúster:** No alteres el comportamiento ya implementado de `cluster.conf`, `cluster-state.config`, `jettra.cluster_state_config_dir` ni el descubrimiento/replicación entre `PRIMARY` y `SECONDARY`.
2. **Stack y estándares del proyecto:** Usa Java 25+, MicroProfile Config, Virtual Threads y **JettraTestRunner** para pruebas (prohibido JUnit o Helidon).
3. **Variables de entorno en `Dockerfile`:** Define valores por defecto razonables con `ENV` para `CLUSTER_NODE_IP`, `CLUSTER_NODE_GRPC_PORT` y `CLUSTER_NODE_REST_PORT` (mapeados a `cluster.node.ip`, `cluster.node.grpc.port` y `cluster.node.rest.port` según convenga en MicroProfile Config), manteniendo `jettra.cluster_state_config_dir` y los volúmenes persistentes necesarios.
4. **Todos los `docker-compose`:** Actualiza todos los archivos `docker-compose` del proyecto **JettraStore** para:
   - Pasar `cluster.node.ip` / `CLUSTER_NODE_IP`, `cluster.node.grpc.port` / `CLUSTER_NODE_GRPC_PORT` y `cluster.node.rest.port` / `CLUSTER_NODE_REST_PORT` en cada servicio.
   - Montar `cluster.conf` de forma opcional/condicional únicamente en servicios que actúen como nodo `PRIMARY`, y omitir el montaje de `cluster.conf` en servicios `SECONDARY`, compartiendo o persistiendo el directorio de `jettra.cluster_state_config_dir`.
5. **Documentación en `JettraStore/guide/book.md`:** Actualiza `JettraStore/guide/book.md` con:
   - Explicación clara del comportamiento `PRIMARY` (con o sin `cluster.conf` hacia `jettra.cluster_state_config_dir`) frente a `SECONDARY` (sin `cluster.conf`, sincronizando desde `PRIMARY`).
   - Tabla o referencia de variables `cluster.node.ip`, `cluster.node.grpc.port`, `cluster.node.rest.port` y `jettra.cluster_state_config_dir`.
   - Comandos `docker build` y ejemplos de `docker-compose` (single-node / multi-node `PRIMARY` + `SECONDARY`).
   - Procedimiento paso a paso para autenticar, etiquetar (`tag`) y subir la imagen a Docker Hub (`docker push`).

## Deliverables
- Todos los `Dockerfile` del proyecto **JettraStore** actualizados con las variables de entorno correspondientes.
- Todos los archivos `docker-compose` del proyecto **JettraStore** actualizados con las variables `cluster.node.ip`, `cluster.node.grpc.port` y `cluster.node.rest.port` y el manejo coherente de `cluster.conf` en `PRIMARY` vs `SECONDARY`.
- Pruebas de validación ejecutadas con `JettraTestRunner` (sin JUnit) verificando la configuración/arranque en entornos de prueba cuando aplique.
- Documentación actualizada en `JettraStore/guide/book.md` incluyendo `docker build`, `docker-compose` y el procedimiento para subir a Docker Hub.
