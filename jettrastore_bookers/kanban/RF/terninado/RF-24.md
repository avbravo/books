# RF-24: Comunicación de `JettraStoreExampleWeb` con `JettraStoreExampleMicroservices` vía `RestClient` + JWT y formularios CRUD en tres categorías

## Contexto
En el ecosistema **JettraStore** (desarrollado en **Java 25+** sobre **Ubuntu 26.04**, con pruebas en **JettraTest**), el proyecto **JettraStoreExampleWeb** debe consumir los endpoints expuestos por **JettraStoreExampleMicroservices** (sobre la base de datos **`example_factura_db`**) de forma segura y estandarizada, ofreciendo interfaces de formularios CRUD organizadas en tres categorías tecnológicas distintas.

## Objetivo
Actualizar **JettraStoreExampleWeb** para que se comunique con los endpoints de **JettraStoreExampleMicroservices** mediante **`RestClient`** y autenticación/seguridad con **JWT** (integrado con el esquema de seguridad / **JettraJWT** del ecosistema), e implementar los formularios completos para las operaciones **CRUD** (crear, consultar/listar, actualizar y eliminar) correspondientes a cada endpoint en tres categorías: **Jakarta Faces**, **JettraFlux** y **Jettra Astra**.

## Requerimientos técnicos y funcionales
1. **Cliente HTTP (`RestClient`) y seguridad JWT:**
   - Configurar clientes basados en **`RestClient`** en **JettraStoreExampleWeb** apuntando a los endpoints de **JettraStoreExampleMicroservices**, centralizando URL base, timeouts, serialización y manejo de errores HTTP.
   - Implementar el flujo de seguridad con **JWT** (envío de token `Authorization: Bearer <token>`, gestión/renovación o propagación del token y manejo de respuestas `401`/`403` o sesiones expiradas).
2. **Categoría 1 — Formularios CRUD con Jakarta Faces:**
   - Crear las vistas/formularios y beans/controladores en **Jakarta Faces** para todas las operaciones CRUD de cada endpoint expuesto por **JettraStoreExampleMicroservices**.
   - Incluir validaciones de entrada, feedback de éxito/error y consumo de los servicios respaldados por `RestClient` + JWT.
3. **Categoría 2 — Formularios CRUD con JettraFlux:**
   - Crear los formularios y flujos reactivos/componentes con **JettraFlux** (manteniendo componentes puros de JettraFlux y sin inyección cruda de HTML/JS/CSS en la lógica ni `window.confirm` nativo) para todas las operaciones CRUD de cada endpoint.
4. **Categoría 3 — Formularios CRUD con Jettra Astra:**
   - Crear los formularios correspondientes para todas las operaciones CRUD de cada endpoint utilizando **Jettra Astra**, manteniendo coherencia de datos, validaciones y consumo mediante `RestClient` + JWT.
5. **Pruebas y validación:**
   - Añadir pruebas con **JettraTest** (sin JUnit) verificando clientes `RestClient`, propagación/validación de JWT y comportamiento de las operaciones CRUD en las tres categorías.
   - Asegurar que el proyecto compile limpiamente en **Java 25+**.

## Entregables y criterios de aceptación
- [ ] **JettraStoreExampleWeb** conectado a los endpoints de **JettraStoreExampleMicroservices** usando **`RestClient`** y **JWT**.
- [ ] Formularios CRUD completos (crear, leer/listar, actualizar, eliminar) implementados para cada endpoint en las tres categorías: **Jakarta Faces**, **JettraFlux** y **Jettra Astra**.
- [ ] Pruebas con **JettraTest** en verde y resumen de archivos creados o modificados por categoría.
