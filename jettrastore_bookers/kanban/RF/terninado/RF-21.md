## Bloque 1 — : Diálogo de confirmación de eliminación de base de datos con JettraFlux (`JettraStoreExample`)

### Problema actual
En **JettraStoreExample**, al hacer clic en el botón para eliminar una base de datos se dispara un diálogo de confirmación estándar de JavaScript (`window.confirm`), rompiendo la coherencia visual y de UX del sistema.

### Requerimientos funcionales
1. Reemplazar el `window.confirm` nativo por un diálogo modal de confirmación implementado con componentes de **JettraFlux**.
2. Mostrar explícitamente el mensaje: `¿Seguro de eliminar la base de datos?` (indicando el nombre de la base de datos seleccionada si el patrón del proyecto lo soporta).
3. Incluir dos acciones claramente diferenciadas:
   - **Confirmar:** ejecuta la eliminación de la base de datos, cierra el diálogo y actualiza la vista/estado reactivo.
   - **Cancelar:** cierra el diálogo sin ejecutar cambios ni llamadas de eliminación.
4. Asegurar que estilos, cierre del modal (clic en cancelar / cierre estándar de JettraFlux) y flujo de eventos sigan las convenciones de **JettraFlux** en **JettraStoreExample**.

## Bloque 2 — Optimización de `mvn clean verify` (`JettraStoreShell` y `JettraStoreExplorer`)

### Problema actual
En **JettraStoreShell** y **JettraStoreExplorer**, el comando `mvn clean verify` tarda demasiado debido a la duración de las suites de prueba con **JettraTest** y a la configuración del ciclo de compilación/verificación de Maven.

### Tareas requeridas
1. **Diagnóstico de cuellos de botella:**
   - Medir y detallar qué fases de Maven (`compile`, `test-compile`, `test`, `verify`, empaquetado) y qué clases/métodos de **JettraTest** consumen más tiempo.
   - Identificar anti-patrones: reinicios repetidos de servidores/nodos/contextos por cada test, esperas fijas (`Thread.sleep`), timeouts largos, o creación redundante de recursos en disco/red.
2. **Refactorización y aceleración de tests (`JettraTest`):**
   - Compartir fixtures/instancias costosas entre pruebas cuando sea seguro, manteniendo aislamiento de datos/estado entre casos.
   - Sustituir esperas fijas por mecanismos de sincronización deterministas y de baja latencia.
   - Separar pruebas unitarias rápidas de pruebas de integración pesadas y habilitar ejecución paralela segura donde no haya conflictos de puertos o archivos.
3. **Optimización de Maven y JVM (Java 25+):**
   - Ajustar `pom.xml` y/o `.mvn/maven.config` (reutilización de forks JVM, flags de rendimiento de Java 25 como `-XX:+UseCompactObjectHeaders` / `-XX:+UseZGC` según convenga, compilación/ejecución paralela).
   - Comparar tiempos reales de `mvn clean verify` (**Antes vs. Después**) en ambos proyectos.
