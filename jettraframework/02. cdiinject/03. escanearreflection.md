
Para registrar las clases de manera automática en el `BeanContainer`, podemos implementar un mecanismo que escanee automáticamente los paquetes especificados y registre todas las clases anotadas con `@Singleton` o `@Prototype`. Esto elimina la necesidad de registrar manualmente cada clase en el contenedor.

A continuación, se describe cómo implementar esta funcionalidad:

---

### Paso 1: Crear un Escáner de Clases
Utilizaremos **reflexión** para escanear paquetes y encontrar clases anotadas. Para simplificar, usaremos una biblioteca llamada **Reflections**, que facilita el escaneo de clases en paquetes.

Primero, agrega la dependencia de Reflections a tu proyecto (si usas Maven):

```xml
<dependency>
    <groupId>org.reflections</groupId>
    <artifactId>reflections</artifactId>
    <version>0.10.2</version>
</dependency>
```

Si no usas Maven, puedes descargar el JAR de Reflections desde su repositorio oficial.

---

### Paso 2: Modificar el `BeanContainer`
Actualizamos el `BeanContainer` para incluir un método que escanee automáticamente las clases anotadas.

```java
import org.reflections.Reflections;
import java.util.Set;

public class BeanContainer {
    private final Map<Class<?>, Object> singletonBeans = new HashMap<>();
    private final Map<Class<?>, Class<?>> beanDefinitions = new HashMap<>();

    public void scanAndRegister(String packageName) {
        Reflections reflections = new Reflections(packageName);

        // Encontrar clases anotadas con @Singleton o @Prototype
        Set<Class<?>> annotatedClasses = reflections.getTypesAnnotatedWith(Singleton.class);
        annotatedClasses.addAll(reflections.getTypesAnnotatedWith(Prototype.class));

        for (Class<?> clazz : annotatedClasses) {
            registerBean(clazz);
        }
    }

    public void registerBean(Class<?> beanClass) {
        if (beanClass.isInterface()) {
            throw new IllegalArgumentException("Cannot register an interface directly: " + beanClass.getName());
        }
        beanDefinitions.put(beanClass, beanClass);

        // Si la clase implementa una interfaz, registramos la relación
        for (Class<?> iface : beanClass.getInterfaces()) {
            beanDefinitions.put(iface, beanClass);
        }
    }

    public <T> T getBean(Class<T> beanClass) {
        Class<?> implementationClass = beanDefinitions.get(beanClass);
        if (implementationClass == null) {
            throw new RuntimeException("No implementation found for: " + beanClass.getName());
        }

        if (implementationClass.isAnnotationPresent(Singleton.class)) {
            return getSingletonBean(implementationClass);
        } else {
            return createNewInstance(implementationClass);
        }
    }

    @SuppressWarnings("unchecked")
    private <T> T getSingletonBean(Class<?> beanClass) {
        return (T) singletonBeans.computeIfAbsent(beanClass, this::createNewInstance);
    }

    @SuppressWarnings("unchecked")
    private <T> T createNewInstance(Class<?> beanClass) {
        try {
            T instance = (T) beanClass.getDeclaredConstructor().newInstance();
            injectDependencies(instance);
            return instance;
        } catch (Exception e) {
            throw new RuntimeException("Failed to create bean: " + beanClass.getName(), e);
        }
    }

    private <T> void injectDependencies(T instance) {
        for (var field : instance.getClass().getDeclaredFields()) {
            if (field.isAnnotationPresent(Inject.class)) {
                field.setAccessible(true);
                Class<?> fieldType = field.getType();
                Object dependency = getBean(fieldType);
                try {
                    field.set(instance, dependency);
                } catch (IllegalAccessException e) {
                    throw new RuntimeException("Failed to inject dependency: " + field.getName(), e);
                }
            }
        }
    }
}
```

---

### Paso 3: Usar el Escáner Automático
Ahora podemos usar el método `scanAndRegister` para registrar automáticamente todas las clases anotadas en un paquete específico.

```java
public class Main {
    public static void main(String[] args) {
        BeanContainer container = new BeanContainer();

        // Escanear y registrar automáticamente todas las clases anotadas en el paquete "com.example"
        container.scanAndRegister("com.example");

        // Obtener beans
        UserService userService = container.getBean(UserService.class);
        userService.addUser("Alice");
        userService.getUser("123");

        // Verificar que el servicio es prototype-scoped
        UserService userService2 = container.getBean(UserService.class);
        System.out.println("Are userService and userService2 the same instance? " + (userService == userService2));
    }
}
```

---

### Estructura del Proyecto
Supongamos que tienes el siguiente paquete y clases:

```
com.example
├── UserRepository.java          (Interfaz)
├── UserRepositoryImpl.java      (Implementación Singleton)
├── UserService.java             (Servicio Prototype)
└── Main.java                    (Clase principal)
```

- `UserRepository`: Interfaz.
- `UserRepositoryImpl`: Implementación anotada con `@Singleton`.
- `UserService`: Servicio anotado con `@Prototype`.

---

### Salida Esperada
Cuando ejecutas el programa, la salida será:

```
Saving user: Alice
Finding user with ID: 123
Retrieved user: User-123
Are userService and userService2 the same instance? false
```

---

### Explicación del Funcionamiento
1. **Escaneo Automático**: El método `scanAndRegister` utiliza Reflections para buscar todas las clases anotadas con `@Singleton` o `@Prototype` en el paquete especificado.
2. **Registro Automático**: Las clases encontradas se registran automáticamente en el `BeanContainer`.
3. **Resolución de Interfaces**: Si una clase implementa una interfaz, el contenedor asocia la interfaz con la implementación.
4. **Inyección de Dependencias**: Las dependencias se inyectan automáticamente en los campos anotados con `@Inject`.

---

### Ventajas
- **Automatización**: No es necesario registrar manualmente cada clase.
- **Escalabilidad**: Puedes agregar nuevas clases sin modificar el código del contenedor.
- **Flexibilidad**: Puedes escanear múltiples paquetes si es necesario.

---

### Consideraciones Adicionales
1. **Calificadores Personalizados**: Si tienes múltiples implementaciones de una interfaz, puedes extender el sistema para usar calificadores personalizados (por ejemplo, `@Named`).
2. **Performance**: El escaneo de clases puede ser costoso en proyectos grandes. Considera realizarlo solo una vez durante la inicialización.
3. **Filtros Avanzados**: Reflections permite filtrar clases por otras anotaciones o criterios, lo que puede ser útil para casos específicos.
