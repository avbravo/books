
Vamos a extender el ejemplo anterior para incluir un segundo repositorio: `CountryRepository`, que maneja países. Esto permitirá demostrar cómo el sistema de inyección de dependencias puede manejar múltiples repositorios y sus respectivas implementaciones.

---

### Paso 1: Definir la Interfaz y la Implementación del Repositorio de Países
Añadimos una nueva interfaz y su implementación:

#### Interfaz `CountryRepository`
```java
public interface CountryRepository {
    void save(String country);
    String find(String id);
}
```

#### Implementación `CountryRepositoryImpl`
```java
@Singleton
public class CountryRepositoryImpl implements CountryRepository {

    @Override
    public void save(String country) {
        System.out.println("Saving country: " + country);
    }

    @Override
    public String find(String id) {
        System.out.println("Finding country with ID: " + id);
        return "Country-" + id;
    }
}
```

---

### Paso 2: Crear un Servicio que Use el Repositorio de Países
Añadimos un servicio que dependa del `CountryRepository`.

#### Servicio `CountryService`
```java
@Prototype
public class CountryService {

    @Inject
    private CountryRepository countryRepository;

    public void addCountry(String country) {
        countryRepository.save(country);
    }

    public void getCountry(String id) {
        String country = countryRepository.find(id);
        System.out.println("Retrieved country: " + country);
    }
}
```

---

### Paso 3: Modificar el Servicio de Administración (`AdminService`)
Actualizamos el `AdminService` para que también use el `CountryService`.

#### Servicio `AdminService`
```java
@Prototype
public class AdminService {

    @Inject
    private UserService userService;

    @Inject
    private CountryService countryService;

    public void manageUser(String user) {
        System.out.println("Admin managing user...");
        userService.addUser(user);
    }

    public void manageCountry(String country) {
        System.out.println("Admin managing country...");
        countryService.addCountry(country);
    }
}
```

---

### Paso 4: Centralizar el Registro en la Clase Principal
La clase `Application` ya está configurada para escanear automáticamente todos los paquetes y registrar las clases anotadas. No es necesario modificarla.

---

### Paso 5: Usar el Contenedor Centralizado
Actualizamos la clase principal (`Main`) para usar tanto el `UserService` como el `CountryService`.

#### Clase Principal `Main`
```java
public class Main {
    public static void main(String[] args) {
        // Inicializar la aplicación y escanear el paquete "com.example"
        Application.initialize("com.example");

        // Obtener beans desde el contenedor centralizado
        UserService userService = Application.getBean(UserService.class);
        CountryService countryService = Application.getBean(CountryService.class);
        AdminService adminService = Application.getBean(AdminService.class);

        // Usar los servicios
        userService.addUser("Alice");
        userService.getUser("123");

        countryService.addCountry("Mexico");
        countryService.getCountry("MX");

        adminService.manageUser("Bob");
        adminService.manageCountry("Canada");

        // Verificar que los servicios son prototype-scoped
        UserService userService2 = Application.getBean(UserService.class);
        System.out.println("Are userService and userService2 the same instance? " + (userService == userService2));
    }
}
```

---

Cuando ejecutas el programa, la salida será:

---

### Explicación del Funcionamiento
1. **Múltiples Repositorios**:
   - El sistema maneja dos repositorios: `UserRepository` y `CountryRepository`.
   - Cada repositorio tiene su propia implementación (`UserRepositoryImpl` y `CountryRepositoryImpl`).

2. **Inyección de Dependencias**:
   - Los servicios (`UserService`, `CountryService`, `AdminService`) reciben automáticamente las dependencias correctas.
   - Por ejemplo, `AdminService` recibe tanto `UserService` como `CountryService`.

3. **Escaneo Automático**:
   - La clase `Application` escanea automáticamente el paquete `com.example` y registra todas las clases anotadas con `@Singleton` o `@Prototype`.

4. **Scopes**:
   - `UserRepositoryImpl` y `CountryRepositoryImpl` son singletons.
   - `UserService`, `CountryService` y `AdminService` son prototype-scoped.

---

### Estructura del Proyecto
El proyecto ahora tiene la siguiente estructura:

```
com.example
├── UserRepository.java          (Interfaz)
├── UserRepositoryImpl.java      (Implementación Singleton)
├── UserService.java             (Servicio Prototype)
├── CountryRepository.java       (Interfaz)
├── CountryRepositoryImpl.java   (Implementación Singleton)
├── CountryService.java          (Servicio Prototype)
├── AdminService.java            (Servicio Prototype)
├── Application.java             (Clase principal para inicializar el contenedor)
└── Main.java                    (Clase principal)
```

---

### Ventajas
1. **Escalabilidad**: Es fácil agregar nuevos repositorios y servicios sin modificar el código existente.
2. **Centralización**: Todo el registro se realiza en la clase `Application`, lo que evita duplicación.
3. **Flexibilidad**: Puedes manejar múltiples repositorios e inyectarlos en diferentes servicios según sea necesario.

---

### Consideraciones Adicionales
1. **Calificadores Personalizados**: Si tienes múltiples implementaciones de una interfaz, puedes extender el sistema para usar calificadores como `@Named`.
2. **Performance**: El escaneo automático puede ser lento en proyectos grandes. Considera realizarlo solo una vez durante la inicialización.
3. **Pruebas Unitarias**: Este diseño facilita las pruebas unitarias, ya que puedes inyectar mocks en los servicios.
