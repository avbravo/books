# CDI  @Inject from Scratch


Creating a simple CDI-like `@Inject` mechanism in Java SE without relying on Jakarta EE or any other external framework involves implementing a basic dependency injection system. Below is a step-by-step guide to creating such a system from scratch.

---

### **1. Define the `@Inject` Annotation**
We start by defining a custom annotation that will be used to mark fields for injection.

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Inject {
}
```

This annotation will be used to mark fields in classes where dependencies need to be injected.

---

### **2. Create a Simple Dependency Injection Container**
The container will manage the creation and injection of objects. It will scan for fields annotated with `@Inject` and inject the appropriate dependencies.

```java
import java.lang.reflect.Field;
import java.util.HashMap;
import java.util.Map;

public class Injector {
    private final Map<Class<?>, Object> instances = new HashMap<>();

    // Register a bean (dependency) with the container
    public <T> void register(Class<T> type, T instance) {
        instances.put(type, instance);
    }

    // Resolve and inject dependencies into an object
    public <T> T inject(T target) {
        Class<?> clazz = target.getClass();
        for (Field field : clazz.getDeclaredFields()) {
            if (field.isAnnotationPresent(Inject.class)) {
                try {
                    field.setAccessible(true); // Allow access to private fields
                    Class<?> fieldType = field.getType();
                    Object dependency = instances.get(fieldType);

                    if (dependency == null) {
                        throw new RuntimeException("No dependency found for type: " + fieldType.getName());
                    }

                    field.set(target, dependency); // Inject the dependency
                } catch (IllegalAccessException e) {
                    throw new RuntimeException("Failed to inject dependency", e);
                }
            }
        }
        return target;
    }
}
```

---

### **3. Example Usage**
Let's create some example classes to demonstrate how this works.

#### **Define Some Classes**
```java
public interface Service {
    void execute();
}

public class EmailService implements Service {
    @Override
    public void execute() {
        System.out.println("Sending email...");
    }
}

public class NotificationManager {
    @Inject
    private Service service;

    public void sendNotification() {
        service.execute();
    }
}
```

Here:
- `Service` is an interface.
- `EmailService` is a concrete implementation of `Service`.
- `NotificationManager` depends on `Service`, and the dependency is marked with `@Inject`.

---

#### **Main Application**
Now, let's use the `Injector` to wire everything together.

```java
public class Main {
    public static void main(String[] args) {
        // Create the injector
        Injector injector = new Injector();

        // Register the dependency
        injector.register(Service.class, new EmailService());

        // Create the object that needs injection
        NotificationManager manager = new NotificationManager();

        // Inject dependencies
        injector.inject(manager);

        // Use the object
        manager.sendNotification();
    }
}
```

---

### **4. Output**
When you run the `Main` class, the output will be:

```
Sending email...
```

---

### **Explanation of How It Works**
1. The `Injector` class maintains a map of registered dependencies (`instances`).
2. When `inject()` is called, it scans the target object's fields for the `@Inject` annotation.
3. For each annotated field, it retrieves the corresponding dependency from the `instances` map and injects it into the field using reflection.
4. If a required dependency is not found in the map, an exception is thrown.

---

### **Limitations**
This implementation is a basic proof of concept and lacks many features of a full-fledged CDI framework:
- It does not support constructor injection.
- It does not handle circular dependencies.
- It assumes all dependencies are manually registered with the container.
- It does not support qualifiers or scopes.

To make it more robust, you could extend it to support additional features like constructor injection, lazy initialization, and singleton scopes.
