Para generar los endpoints del ejemplo anterior utilizando **Java Annotation Processing**, podemos automatizar la creación de los handlers y las rutas HTTP basadas en anotaciones personalizadas. Esto permite que el código sea más modular y fácil de mantener, ya que las rutas y los métodos HTTP se generan automáticamente a partir de las anotaciones.

### 1. Concepto básico

La idea es crear una anotación personalizada (por ejemplo, `@Endpoint`) que se pueda usar para marcar clases o métodos que deben ser expuestos como endpoints HTTP. Luego, un procesador de anotaciones generará el código necesario para registrar estos endpoints en el servidor HTTP.

### 2. Estructura del proyecto

El proyecto tendrá las siguientes partes:

1. **Anotación personalizada (`@Endpoint`)**: Para marcar las clases o métodos que deben ser endpoints.
2. **Procesador de anotaciones**: Genera el código necesario para registrar los endpoints.
3. **Clase principal del servidor**: Inicia el servidor HTTP y utiliza los endpoints generados.

### 3. Implementación paso a paso

#### **Paso 1: Crear la anotación `@Endpoint`**

Primero, creamos una anotación personalizada llamada `@Endpoint`. Esta anotación se usará para marcar las clases que representan endpoints.

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.SOURCE)
@Target(ElementType.TYPE)
public @interface Endpoint {
    String path();
}
```

- `path()`: Define la ruta del endpoint (por ejemplo, `/personas`).
- `@Retention(RetentionPolicy.SOURCE)`: Indica que la anotación solo estará disponible durante la fase de compilación.

#### **Paso 2: Procesador de anotaciones**

El procesador de anotaciones buscará todas las clases anotadas con `@Endpoint` y generará el código necesario para registrar los endpoints en el servidor HTTP.

```java
import javax.annotation.processing.AbstractProcessor;
import javax.annotation.processing.RoundEnvironment;
import javax.annotation.processing.SupportedAnnotationTypes;
import javax.annotation.processing.SupportedSourceVersion;
import javax.lang.model.SourceVersion;
import javax.lang.model.element.Element;
import javax.lang.model.element.TypeElement;
import javax.tools.JavaFileObject;
import java.io.IOException;
import java.io.PrintWriter;
import java.util.Set;

@SupportedAnnotationTypes("Endpoint")
@SupportedSourceVersion(SourceVersion.RELEASE_8)
public class EndpointProcessor extends AbstractProcessor {

    @Override
    public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
        // Iterar sobre todos los elementos anotados con @Endpoint
        for (Element element : roundEnv.getElementsAnnotatedWith(Endpoint.class)) {
            if (element instanceof TypeElement) {
                TypeElement typeElement = (TypeElement) element;
                Endpoint endpointAnnotation = typeElement.getAnnotation(Endpoint.class);
                String path = endpointAnnotation.path();
                String className = typeElement.getSimpleName().toString();

                // Generar el código para registrar el endpoint
                try {
                    generateHandlerCode(className, path);
                } catch (IOException e) {
                    e.printStackTrace();
                }
            }
        }
        return true;
    }

    private void generateHandlerCode(String className, String path) throws IOException {
        // Nombre del archivo generado
        String handlerClassName = className + "Handler";
        JavaFileObject builderFile = processingEnv.getFiler().createSourceFile(handlerClassName);

        // Escribir el código del handler
        try (PrintWriter out = new PrintWriter(builderFile.openWriter())) {
            out.println("import com.sun.net.httpserver.HttpHandler;");
            out.println("import com.sun.net.httpserver.HttpExchange;");
            out.println("import java.io.IOException;");
            out.println("import java.io.OutputStream;");
            out.println();
            out.println("public class " + handlerClassName + " implements HttpHandler {");
            out.println("    @Override");
            out.println("    public void handle(HttpExchange exchange) throws IOException {");
            out.println("        String response = \"Endpoint: " + path + "\";");
            out.println("        exchange.sendResponseHeaders(200, response.getBytes().length);");
            out.println("        OutputStream os = exchange.getResponseBody();");
            out.println("        os.write(response.getBytes());");
            out.println("        os.close();");
            out.println("    }");
            out.println("}");
        }
    }
}
```

Este procesador genera una clase `Handler` para cada clase anotada con `@Endpoint`. La clase generada implementa `HttpHandler` y responde con un mensaje simple que indica la ruta del endpoint.

#### **Paso 3: Clase principal del servidor**

Ahora, creamos la clase principal del servidor que registrará los endpoints generados.

```java
import com.sun.net.httpserver.HttpServer;

import java.io.IOException;
import java.net.InetSocketAddress;

public class MainServer {

    public static void main(String[] args) throws IOException {
        // Crear una instancia del servidor HTTP
        HttpServer server = HttpServer.create(new InetSocketAddress(8080), 0);

        // Registrar los endpoints generados
        server.createContext("/personas", new PersonasHandler());
        server.createContext("/productos", new ProductosHandler());

        // Iniciar el servidor
        server.setExecutor(null); // Usa el executor por defecto
        server.start();
        System.out.println("Servidor iniciado en http://localhost:8080");
    }
}
```

#### **Paso 4: Ejemplo de clase anotada**

Finalmente, creamos una clase anotada con `@Endpoint`.

```java
@Endpoint(path = "/personas")
public class Personas {
    // Aquí podrías tener lógica adicional para manejar personas
}
```

Cuando compiles este proyecto, el procesador de anotaciones generará una clase `PersonasHandler` que implementa `HttpHandler` y registra el endpoint `/personas`.

#### **Paso 5: Compilación y ejecución**

Para compilar y ejecutar el proyecto, sigue estos pasos:

1. Asegúrate de que el procesador de anotaciones esté correctamente configurado en tu proyecto.
2. Compila el proyecto:
   ```bash
   javac -processor EndpointProcessor MainServer.java Personas.java
   ```
3. Ejecuta el servidor:
   ```bash
   java MainServer
   ```

Ahora, cuando accedas a `http://localhost:8080/personas`, deberías ver la respuesta generada por el `PersonasHandler`.

### 4. Explicación del flujo

1. **Anotación `@Endpoint`**: Marca las clases que deben ser endpoints.
2. **Procesador de anotaciones**: Busca las clases anotadas con `@Endpoint` y genera una clase `Handler` para cada una.
3. **Clase principal del servidor**: Registra los handlers generados en el servidor HTTP.
4. **Generación automática**: El procesador de anotaciones genera el código necesario para manejar las solicitudes HTTP.

### 5. Ventajas de usar Annotation Processing

- **Automatización**: Los endpoints se generan automáticamente a partir de las anotaciones, lo que reduce la cantidad de código repetitivo.
- **Modularidad**: Las clases que representan los recursos (como `Personas`) están separadas del código que maneja las solicitudes HTTP.
- **Facilidad de mantenimiento**: Si necesitas agregar nuevos endpoints, simplemente anota una nueva clase con `@Endpoint`.

### 6. Limitaciones

- **Complejidad**: El uso de annotation processing puede aumentar la complejidad del proyecto, especialmente si no estás familiarizado con esta técnica.
- **Persistencia**: Este ejemplo almacena los datos en memoria. Para una aplicación real, deberías usar una base de datos para persistir los datos.

### Conclusión

Usar **Java Annotation Processing** para generar endpoints es una forma poderosa de automatizar la creación de rutas HTTP en aplicaciones Java. Este enfoque es ideal para proyectos donde deseas mantener el código limpio y modular, especialmente cuando tienes muchos endpoints que manejan diferentes recursos. Sin embargo, para aplicaciones más grandes y complejas, considera usar frameworks como Spring Boot, que ofrecen funcionalidades similares de manera más robusta.
