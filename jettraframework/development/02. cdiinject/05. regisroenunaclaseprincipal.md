
Para evitar duplicar el código de registro en cada clase, podemos centralizar el proceso de escaneo y registro en una clase principal (por ejemplo, `Application`). Esta clase será responsable de inicializar el contenedor (`BeanContainer`), escanear los paquetes y registrar todas las clases anotadas. Luego, cualquier otra clase puede usar el mismo contenedor para obtener beans sin necesidad de registrarlos nuevamente.

A continuación, te muestro un ejemplo completo con varias clases que usan inyección de dependencias y cómo centralizar el registro en la clase principal.

---

### Paso 1: Definir las Clases y Anotaciones
Definimos varias clases con diferentes roles (repositorios, servicios) y sus respectivas interfaces.

#### Interfaz y Repositorio
```java
public interface UserRepository {
    void save(String user);
    String find(String id);
}

@Singleton
public class UserRepositoryImpl implements UserRepository {

    @Override
    public void save(String user) {
        System.out.println("Saving user: " + user);
    }

    @Override
    public String find(String id) {
        System.out.println("Finding user with ID: " + id);
        return "User-" + id;
    }
}
```

---

#### Servicio que Usa el Repositorio
```java
@Prototype
public class UserService {

    @Inject
    private UserRepository userRepository;

    public void addUser(String user) {
        userRepository.save(user);
    }

    public void getUser(String id) {
        String user = userRepository.find(id);
        System.out.println("Retrieved user: " + user);
    }
}
```

---

#### Otro Servicio que Depende del Primer Servicio
```java
@Prototype
public class AdminService {

    @Inject
    private UserService userService;

    public void manageUser(String user) {
        System.out.println("Admin managing user...");
        userService.addUser(user);
    }
}
```

---

### Paso 2: Centralizar el Registro en la Clase Principal
Creamos una clase `Application` que se encargue de inicializar el contenedor y escanear automáticamente los paquetes.

```java
public class Application {

    private static final BeanContainer container = new BeanContainer();

    /**
     * Inicializa la aplicación y registra todas las clases anotadas.
     */
    public static void initialize(String packageName) {
        // Escanear y registrar automáticamente todas las clases anotadas
        container.scanAndRegister(packageName);
    }

    /**
     * Obtiene una instancia de un bean del contenedor.
     */
    public static <T> T getBean(Class<T> beanClass) {
        return container.getBean(beanClass);
    }
}
```

---

### Paso 3: Modificar el `BeanContainer`
El `BeanContainer` ya está implementado en ejemplos anteriores. Asegúrate de que tenga el método `scanAndRegister` para escanear paquetes y registrar clases automáticamente.

---

### Paso 4: Usar el Contenedor Centralizado
Ahora, cualquier clase puede usar el contenedor centralizado a través de la clase `Application`.

#### Ejemplo de Uso en la Clase Principal
```java
public class Main {
    public static void main(String[] args) {
        // Inicializar la aplicación y escanear el paquete "com.example"
        Application.initialize("com.example");

        // Obtener beans desde el contenedor centralizado
        UserService userService = Application.getBean(UserService.class);
        AdminService adminService = Application.getBean(AdminService.class);

        // Usar los servicios
        userService.addUser("Alice");
        userService.getUser("123");

        adminService.manageUser("Bob");

        // Verificar que los servicios son prototype-scoped
        UserService userService2 = Application.getBean(UserService.class);
        System.out.println("Are userService and userService2 the same instance? " + (userService == userService2));
    }
}
```

---

### Salida Esperada
Cuando ejecutas el programa, la salida será:

```
Saving user: Alice
Finding user with ID: 123
Retrieved user: User-123
Admin managing user...
Saving user: Bob
Are userService and userService2 the same instance? false
```

---

### Explicación del Funcionamiento
1. **Centralización**:
   - La clase `Application` es responsable de inicializar el contenedor y escanear los paquetes.
   - Todas las clases usan el mismo contenedor a través de `Application.getBean()`.

2. **Escaneo Automático**:
   - El método `scanAndRegister` busca todas las clases anotadas con `@Singleton` o `@Prototype` en el paquete especificado.

3. **Inyección de Dependencias**:
   - Las dependencias se inyectan automáticamente en los campos anotados con `@Inject`.

4. **Reutilización del Contenedor**:
   - No es necesario registrar manualmente las clases en cada clase. Todo se gestiona desde la clase `Application`.

---

### Estructura del Proyecto
Supongamos que tienes el siguiente paquete y clases:

```
com.example
├── UserRepository.java          (Interfaz)
├── UserRepositoryImpl.java      (Implementación Singleton)
├── UserService.java             (Servicio Prototype)
├── AdminService.java            (Servicio Prototype)
├── Application.java             (Clase principal para inicializar el contenedor)
└── Main.java                    (Clase principal)
```

---

### Ventajas
1. **Evita Duplicación**: El registro se realiza solo una vez en la clase `Application`.
2. **Facilidad de Mantenimiento**: Si agregas nuevas clases, no necesitas modificar el código de registro.
3. **Centralización**: Todas las clases usan el mismo contenedor, lo que garantiza consistencia.

---

### Consideraciones Adicionales
1. **Paquetes Múltiples**: Si tienes múltiples paquetes, puedes llamar a `scanAndRegister` para cada uno.
2. **Calificadores Personalizados**: Si necesitas manejar múltiples implementaciones de una interfaz, puedes extender el sistema para usar calificadores como `@Named`.
3. **Performance**: El escaneo automático puede ser lento en proyectos grandes. Considera realizarlo solo una vez durante la inicialización.
