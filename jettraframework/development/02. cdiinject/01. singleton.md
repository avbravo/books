
# Create CDI Inject from scratch in Java SE not user jakarta CDI 

Creating a basic CDI (Contexts and Dependency Injection) framework from scratch in Java SE without using Jakarta CDI involves implementing the core concepts of dependency injection manually. These concepts include:

1. **Dependency Injection**: Automatically providing dependencies to components.
2. **Scopes**: Managing the lifecycle of objects (e.g., singleton, prototype).
3. **Qualifiers**: Allowing fine-grained control over which implementation is injected.

Below is a step-by-step implementation of a simple CDI-like framework in Java SE:

---

### Step 1: Define Annotations for Scopes and Qualifiers
We need custom annotations to define scopes and qualifiers.

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME)
public @interface Singleton {}

@Retention(RetentionPolicy.RUNTIME)
public @interface Prototype {}

@Retention(RetentionPolicy.RUNTIME)
public @interface Named {
    String value() default "";
}
```

- `@Singleton`: Indicates that only one instance of the bean should be created.
- `@Prototype`: Indicates that a new instance should be created every time.
- `@Named`: Allows us to give a name to a bean for disambiguation.

---

### Step 2: Create a Bean Container
The container will manage the creation and injection of beans.

```java
import java.util.HashMap;
import java.util.Map;

public class BeanContainer {
    private final Map<Class<?>, Object> singletonBeans = new HashMap<>();
    private final Map<Class<?>, Class<?>> beanDefinitions = new HashMap<>();

    public void registerBean(Class<?> beanClass) {
        beanDefinitions.put(beanClass, beanClass);
    }

    public <T> T getBean(Class<T> beanClass) {
        if (beanClass.isAnnotationPresent(Singleton.class)) {
            return getSingletonBean(beanClass);
        } else {
            return createNewInstance(beanClass);
        }
    }

    @SuppressWarnings("unchecked")
    private <T> T getSingletonBean(Class<T> beanClass) {
        return (T) singletonBeans.computeIfAbsent(beanClass, this::createNewInstance);
    }

    @SuppressWarnings("unchecked")
    private <T> T createNewInstance(Class<T> beanClass) {
        try {
            T instance = beanClass.getDeclaredConstructor().newInstance();
            injectDependencies(instance);
            return instance;
        } catch (Exception e) {
            throw new RuntimeException("Failed to create bean: " + beanClass.getName(), e);
        }
    }

    private <T> void injectDependencies(T instance) {
        for (var field : instance.getClass().getDeclaredFields()) {
            if (field.isAnnotationPresent(Inject.class)) {
                field.setAccessible(true);
                Class<?> fieldType = field.getType();
                Object dependency = getBean(fieldType);
                try {
                    field.set(instance, dependency);
                } catch (IllegalAccessException e) {
                    throw new RuntimeException("Failed to inject dependency: " + field.getName(), e);
                }
            }
        }
    }
}
```

- `singletonBeans`: Stores singleton instances.
- `beanDefinitions`: Maps bean classes to their definitions.
- `getBean`: Retrieves or creates a bean based on its scope.
- `injectDependencies`: Injects dependencies into fields annotated with `@Inject`.

---

### Step 3: Define the `@Inject` Annotation
This annotation marks fields where dependencies should be injected.

```java
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;

@Retention(RetentionPolicy.RUNTIME)
public @interface Inject {}
```

---

### Step 4: Example Beans
Define some example beans to demonstrate dependency injection.

```java
@Singleton
public class ServiceA {
    public void doSomething() {
        System.out.println("ServiceA is doing something.");
    }
}

@Prototype
public class ServiceB {
    @Inject
    private ServiceA serviceA;

    public void performTask() {
        System.out.println("ServiceB is performing a task.");
        serviceA.doSomething();
    }
}
```

- `ServiceA` is a singleton bean.
- `ServiceB` is a prototype bean with a dependency on `ServiceA`.

---

### Step 5: Main Application
Use the `BeanContainer` to manage and inject beans.

```java
public class Main {
    public static void main(String[] args) {
        BeanContainer container = new BeanContainer();

        // Register beans
        container.registerBean(ServiceA.class);
        container.registerBean(ServiceB.class);

        // Get beans
        ServiceB serviceB1 = container.getBean(ServiceB.class);
        ServiceB serviceB2 = container.getBean(ServiceB.class);

        // Test dependency injection
        serviceB1.performTask();
        serviceB2.performTask();

        // Check if ServiceB is prototype-scoped
        System.out.println("Are serviceB1 and serviceB2 the same instance? " + (serviceB1 == serviceB2));
    }
}
```

---

### Output
When you run the `Main` class, the output will look like this:

```
ServiceB is performing a task.
ServiceA is doing something.
ServiceB is performing a task.
ServiceA is doing something.
Are serviceB1 and serviceB2 the same instance? false
```

---

### Explanation of the Output
1. `ServiceA` is a singleton, so the same instance is shared across all injections.
2. `ServiceB` is prototype-scoped, so a new instance is created each time `getBean` is called.
3. Dependency injection works seamlessly, as `ServiceB` receives the `ServiceA` instance automatically.

### Key Points
- This implementation demonstrates the core principles of CDI: dependency injection, scopes, and qualifiers.
- It is a simplified version and lacks advanced features like interceptors, events, or producer methods.
- For production use, consider leveraging existing frameworks like Jakarta CDI or Spring, which provide robust and feature-rich implementations.
