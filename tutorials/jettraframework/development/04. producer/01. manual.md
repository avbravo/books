
En Java SE (Standard Edition), no tienes acceso a CDI ni a la anotación `@Produces`, ya que estas son parte de Java EE o Jakarta EE. Sin embargo, puedes implementar un sistema similar desde cero utilizando patrones de diseño como **Factory** y **Dependency Injection (DI)** manualmente. A continuación, te muestro cómo crear una implementación básica de inyección de dependencias en Java SE.

---

### **Implementación desde cero**

#### **1. Definición del problema**
Queremos:
- Crear un sistema donde las dependencias sean "inyectadas" automáticamente.
- Permitir que el usuario defina productores para ciertos tipos de objetos.
- Mantenerlo simple y funcional sin usar frameworks externos.

#### **2. Código completo**

```java
import java.util.HashMap;
import java.util.Map;
import java.util.function.Supplier;

// Interfaz común
interface SaludoService {
    String saludar();
}

// Implementación 1
class SaludoFormal implements SaludoService {
    @Override
    public String saludar() {
        return "Estimado usuario, bienvenido.";
    }
}

// Implementación 2
class SaludoInformal implements SaludoService {
    @Override
    public String saludar() {
        return "Hola, ¿cómo estás?";
    }
}

// Clase cliente que usa la inyección
class ClienteSaludo {

    private final SaludoService saludoService;

    // Constructor para inyectar la dependencia
    public ClienteSaludo(SaludoService saludoService) {
        this.saludoService = saludoService;
    }

    public void mostrarSaludo() {
        System.out.println(saludoService.saludar());
    }
}

// Sistema de inyección de dependencias personalizado
class DependencyInjector {

    // Mapa para almacenar los productores de dependencias
    private final Map<Class<?>, Supplier<?>> producers = new HashMap<>();

    // Método para registrar un productor
    public <T> void registerProducer(Class<T> type, Supplier<T> producer) {
        producers.put(type, producer);
    }

    // Método para obtener una instancia de un tipo registrado
    @SuppressWarnings("unchecked")
    public <T> T getInstance(Class<T> type) {
        Supplier<?> producer = producers.get(type);
        if (producer == null) {
            throw new IllegalArgumentException("No producer registered for type: " + type.getName());
        }
        return (T) producer.get();
    }
}

// Clase principal para probar el sistema
public class Main {

    public static void main(String[] args) {
        // Crear el inyector de dependencias
        DependencyInjector injector = new DependencyInjector();

        // Registrar un productor para SaludoService
        injector.registerProducer(SaludoService.class, () -> {
            boolean esFormal = true; // Ejemplo de condición
            if (esFormal) {
                return new SaludoFormal();
            } else {
                return new SaludoInformal();
            }
        });

        // Obtener una instancia de SaludoService
        SaludoService saludoService = injector.getInstance(SaludoService.class);

        // Crear el cliente y pasarle la dependencia
        ClienteSaludo cliente = new ClienteSaludo(saludoService);

        // Mostrar el saludo
        cliente.mostrarSaludo();
    }
}
```

---

### **Explicación del código**

1. **Interfaz y clases concretas (`SaludoService`, `SaludoFormal`, `SaludoInformal`)**:
   - Definimos una interfaz común (`SaludoService`) y dos implementaciones (`SaludoFormal` y `SaludoInformal`).

2. **Clase cliente (`ClienteSaludo`)**:
   - Esta clase depende de `SaludoService`. Recibe la dependencia a través de su constructor (inyección de dependencias manual).

3. **Sistema de inyección de dependencias (`DependencyInjector`)**:
   - Usamos un mapa (`producers`) para almacenar los productores de dependencias.
   - El método `registerProducer` permite registrar un productor para un tipo específico.
   - El método `getInstance` obtiene una instancia del tipo registrado usando el productor correspondiente.

4. **Lógica principal (`Main`)**:
   - Creamos una instancia de `DependencyInjector`.
   - Registramos un productor para `SaludoService` que decide dinámicamente qué implementación usar.
   - Obtenemos una instancia de `SaludoService` y la inyectamos en `ClienteSaludo`.

---

### **Salida esperada**
Si ejecutas el programa, verás algo como esto:

```
Estimado usuario, bienvenido.
```

Si cambias la condición `boolean esFormal = true;` a `false`, la salida será:

```
Hola, ¿cómo estás?
```

---

### **Ventajas de esta implementación**
1. **Simple y ligera**: No depende de frameworks externos.
2. **Flexible**: Puedes registrar cualquier tipo de productor según tus necesidades.
3. **Extensible**: Puedes agregar más funcionalidades, como manejo de ciclos de vida o resolución automática de dependencias.

---

### **Limitaciones**
1. **Manual**: Debes registrar cada productor explícitamente.
2. **Sin anotaciones**: No hay soporte para anotaciones como `@Inject` o `@Produces`. Todo se hace manualmente.
3. **Básico**: Este sistema es muy simple y no incluye características avanzadas como scope management o proxies.

Si necesitas algo más robusto, podrías considerar usar frameworks como **Spring** o **Guice**, pero este ejemplo demuestra cómo implementar un sistema básico de inyección de dependencias en Java SE desde cero. 😊
