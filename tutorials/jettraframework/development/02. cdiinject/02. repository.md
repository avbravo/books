
# Repository CDI

Vamos a extender el ejemplo anterior para incluir interfaces y repositorios. Esto es común en aplicaciones donde se define una interfaz para un repositorio (por ejemplo, `UserRepository`) y se implementa concreta (`UserRepositoryImpl`). Luego, el framework de inyección de dependencias debe ser capaz de resolver la implementación correcta cuando se solicita la interfaz.

---

### Paso 1: Definir la Interfaz del Repositorio
Primero, definimos una interfaz para el repositorio:

```java
public interface UserRepository {
    void save(String user);
    String find(String id);
}
```

---

### Paso 2: Implementar la Interfaz
Creamos una implementación concreta del repositorio:

```java
@Singleton
public class UserRepositoryImpl implements UserRepository {

    @Override
    public void save(String user) {
        System.out.println("Saving user: " + user);
    }

    @Override
    public String find(String id) {
        System.out.println("Finding user with ID: " + id);
        return "User-" + id;
    }
}
```

- La anotación `@Singleton` asegura que solo haya una instancia de `UserRepositoryImpl`.

---

### Paso 3: Crear un Servicio que Use el Repositorio
Definimos un servicio que depende del repositorio:

```java
@Prototype
public class UserService {

    @Inject
    private UserRepository userRepository;

    public void addUser(String user) {
        userRepository.save(user);
    }

    public void getUser(String id) {
        String user = userRepository.find(id);
        System.out.println("Retrieved user: " + user);
    }
}
```

- El servicio `UserService` tiene una dependencia en `UserRepository`, que será inyectada automáticamente.

---

### Paso 4: Modificar el Contenedor para Resolver Interfaces
Actualizamos el `BeanContainer` para manejar interfaces. Cuando se solicita una interfaz, el contenedor buscará la implementación registrada.

```java
import java.util.HashMap;
import java.util.Map;

public class BeanContainer {
    private final Map<Class<?>, Object> singletonBeans = new HashMap<>();
    private final Map<Class<?>, Class<?>> beanDefinitions = new HashMap<>();

    public void registerBean(Class<?> beanClass) {
        if (beanClass.isInterface()) {
            throw new IllegalArgumentException("Cannot register an interface directly: " + beanClass.getName());
        }
        beanDefinitions.put(beanClass, beanClass);

        // Si la clase implementa una interfaz, registramos la relación
        for (Class<?> iface : beanClass.getInterfaces()) {
            beanDefinitions.put(iface, beanClass);
        }
    }

    public <T> T getBean(Class<T> beanClass) {
        Class<?> implementationClass = beanDefinitions.get(beanClass);
        if (implementationClass == null) {
            throw new RuntimeException("No implementation found for: " + beanClass.getName());
        }

        if (implementationClass.isAnnotationPresent(Singleton.class)) {
            return getSingletonBean(implementationClass);
        } else {
            return createNewInstance(implementationClass);
        }
    }

    @SuppressWarnings("unchecked")
    private <T> T getSingletonBean(Class<?> beanClass) {
        return (T) singletonBeans.computeIfAbsent(beanClass, this::createNewInstance);
    }

    @SuppressWarnings("unchecked")
    private <T> T createNewInstance(Class<?> beanClass) {
        try {
            T instance = (T) beanClass.getDeclaredConstructor().newInstance();
            injectDependencies(instance);
            return instance;
        } catch (Exception e) {
            throw new RuntimeException("Failed to create bean: " + beanClass.getName(), e);
        }
    }

    private <T> void injectDependencies(T instance) {
        for (var field : instance.getClass().getDeclaredFields()) {
            if (field.isAnnotationPresent(Inject.class)) {
                field.setAccessible(true);
                Class<?> fieldType = field.getType();
                Object dependency = getBean(fieldType);
                try {
                    field.set(instance, dependency);
                } catch (IllegalAccessException e) {
                    throw new RuntimeException("Failed to inject dependency: " + field.getName(), e);
                }
            }
        }
    }
}
```

- Ahora el contenedor puede resolver interfaces buscando la implementación registrada.

---

### Paso 5: Registrar Beans y Probar
Finalmente, registramos los beans y probamos la funcionalidad.

```java
public class Main {
    public static void main(String[] args) {
        BeanContainer container = new BeanContainer();

        // Registrar beans
        container.registerBean(UserRepositoryImpl.class); // Registra la implementación
        container.registerBean(UserService.class);

        // Obtener el servicio
        UserService userService = container.getBean(UserService.class);

        // Usar el servicio
        userService.addUser("Alice");
        userService.getUser("123");

        // Verificar que el servicio es prototype-scoped
        UserService userService2 = container.getBean(UserService.class);
        System.out.println("Are userService and userService2 the same instance? " + (userService == userService2));
    }
}
```

---

### Salida Esperada
Cuando ejecutas el programa, la salida será:

```
Saving user: Alice
Finding user with ID: 123
Retrieved user: User-123
Are userService and userService2 the same instance? false
```

---

### Explicación de la Salida
1. **Inyección de Dependencias**: El `UserService` recibe automáticamente la implementación de `UserRepository` (`UserRepositoryImpl`).
2. **Scopes**:
   - `UserRepositoryImpl` es un singleton, por lo que solo hay una instancia.
   - `UserService` es prototype-scoped, por lo que cada llamada a `getBean` crea una nueva instancia.
3. **Resolución de Interfaces**: El contenedor resuelve correctamente la interfaz `UserRepository` y proporciona la implementación registrada.

---

### Resumen
Este ejemplo demuestra cómo manejar interfaces y repositorios en un sistema de inyección de dependencias personalizado. El contenedor ahora puede:
1. Resolver interfaces y proporcionar implementaciones.
2. Manejar diferentes scopes (singleton y prototype).
3. Inyectar dependencias automáticamente.

Si necesitas más características, como calificadores personalizados o soporte para múltiples implementaciones de una interfaz, ¡házmelo saber!
