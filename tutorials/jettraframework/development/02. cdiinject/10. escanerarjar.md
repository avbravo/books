
Para mejorar el ejemplo y permitir que el `ClassScanner` lea clases tanto de directorios como de archivos JAR, necesitamos extender la funcionalidad del escáner para manejar entradas ZIP (que es el formato interno de los archivos JAR). Esto implica usar la API `java.util.zip` para procesar los archivos dentro del JAR.

A continuación, te muestro cómo modificar el `ClassScanner` para soportar la lectura de clases desde archivos JAR.

---

### Paso 1: Modificar el `ClassScanner`
Actualizamos el `ClassScanner` para manejar tanto directorios como archivos JAR.

```java
import java.io.File;
import java.io.IOException;
import java.net.URL;
import java.util.ArrayList;
import java.util.Enumeration;
import java.util.List;
import java.util.jar.JarEntry;
import java.util.jar.JarFile;

public class ClassScanner {

    public static List<Class<?>> scanPackage(String packageName) {
        List<Class<?>> classes = new ArrayList<>();
        String packagePath = packageName.replace('.', '/');
        ClassLoader classLoader = Thread.currentThread().getContextClassLoader();

        try {
            Enumeration<URL> resources = classLoader.getResources(packagePath);
            while (resources.hasMoreElements()) {
                URL resource = resources.nextElement();
                if (resource.getProtocol().equals("file")) {
                    // Si es un directorio en el sistema de archivos
                    File directory = new File(resource.getFile());
                    findClassesInDirectory(directory, packageName, classes);
                } else if (resource.getProtocol().equals("jar")) {
                    // Si es un archivo JAR
                    String jarFilePath = resource.getPath().substring(5, resource.getPath().indexOf("!"));
                    findClassesInJar(jarFilePath, packagePath, packageName, classes);
                }
            }
        } catch (IOException e) {
            throw new RuntimeException("Failed to scan package: " + packageName, e);
        }

        return classes;
    }

    private static void findClassesInDirectory(File directory, String packageName, List<Class<?>> classes) {
        File[] files = directory.listFiles();
        if (files == null) {
            return;
        }

        for (File file : files) {
            if (file.isDirectory()) {
                findClassesInDirectory(file, packageName + "." + file.getName(), classes);
            } else if (file.getName().endsWith(".class")) {
                String className = packageName + '.' + file.getName().substring(0, file.getName().length() - 6);
                try {
                    Class<?> clazz = Class.forName(className);
                    classes.add(clazz);
                } catch (ClassNotFoundException e) {
                    throw new RuntimeException("Failed to load class: " + className, e);
                }
            }
        }
    }

    private static void findClassesInJar(String jarFilePath, String packagePath, String packageName, List<Class<?>> classes) {
        try (JarFile jarFile = new JarFile(jarFilePath)) {
            Enumeration<JarEntry> entries = jarFile.entries();
            while (entries.hasMoreElements()) {
                JarEntry entry = entries.nextElement();
                String entryName = entry.getName();

                if (entryName.startsWith(packagePath) && entryName.endsWith(".class")) {
                    String className = entryName.substring(0, entryName.length() - 6).replace('/', '.');
                    try {
                        Class<?> clazz = Class.forName(className);
                        classes.add(clazz);
                    } catch (ClassNotFoundException e) {
                        throw new RuntimeException("Failed to load class: " + className, e);
                    }
                }
            }
        } catch (IOException e) {
            throw new RuntimeException("Failed to read JAR file: " + jarFilePath, e);
        }
    }
}
```

---

### Paso 2: Explicación de los Cambios
1. **Soporte para Directorios**:
   - Si el recurso es un directorio (`file`), se utiliza el método existente `findClassesInDirectory`.

2. **Soporte para Archivos JAR**:
   - Si el recurso es un archivo JAR (`jar`), extraemos su ruta usando `resource.getPath()` y lo procesamos con `findClassesInJar`.
   - Usamos `java.util.jar.JarFile` para leer las entradas del archivo JAR.
   - Filtramos las entradas que pertenecen al paquete especificado y terminan con `.class`.

3. **Carga de Clases**:
   - Para cada archivo `.class` encontrado, construimos el nombre completo de la clase (incluyendo el paquete) y lo cargamos con `Class.forName`.

### Paso 3: Probar el Escáner Mejorado
Ahora puedes probar el escáner mejorado en un proyecto que incluya clases tanto en directorios como en archivos JAR.

#### Ejemplo de Uso
Supongamos que tienes las siguientes clases en tu proyecto:

1. **Clases en el Sistema de Archivos**:
   - `com.example.UserRepositoryImpl`
   - `com.example.UserService`

2. **Clases en un Archivo JAR**:
   - `com.example.CountryRepositoryImpl`
   - `com.example.CountryService`

El escáner detectará automáticamente todas estas clases.

Cuando ejecutas el programa, el escáner imprimirá las clases encontradas. Por ejemplo:

### Paso 5: Integración con el Contenedor

---

### Ventajas del Escáner Mejorado
1. **Compatibilidad con JARs**: Ahora puedes escanear clases tanto en directorios como en archivos JAR.
2. **Escalabilidad**: Funciona en proyectos grandes donde las clases pueden estar empaquetadas en múltiples JARs.
3. **Flexibilidad**: Puedes escanear cualquier paquete, independientemente de su ubicación.

---

### Consideraciones Adicionales
1. **Rendimiento**: Escanear archivos JAR puede ser más lento que escanear directorios, especialmente si hay muchos archivos o clases.
2. **Seguridad**: Algunos entornos restringen el acceso a ciertos recursos. Asegúrate de tener permisos adecuados.
3. **Filtros Avanzados**: Puedes extender el escáner para filtrar clases por anotaciones específicas o criterios personalizados.

Con esta mejora, el escáner es más robusto y puede manejar proyectos complejos que incluyen clases en JARs. ¡Espero que esto sea útil! 😊
