## Entidades
 La especificación [Jakarta Persistence](https://jakarta.ee/specifications/persistence/3.1/jakarta-persistence-spec-3.1.html#entities), 
define una entidad como "Una entidad es un objeto de dominio persistente y ligero.
El principal artefacto de programación es la clase de entidad. Una clase de 
entidad puede hacer uso de clases auxiliares que sirven como clases de ayuda o 
que se utilizan para representar el estado de la entidad.".
La especificación [Jakarta NoSQL](https://jakarta.ee/specifications/nosql/1.0/nosql-1.0.0-b3.html#_element_entity=) , 
la define como "La Entidad es el cuerpo de la información que va a la base de 
datos; cada base de datos tiene una Entidad". 
 Estas especificaciones nos ayudan a comprender que las entidades representan 
tablas de una base de datos relacionales, 
o colecciones o columnas de bases de datos NoSQL. Las cuales serán mapeadas a 
objetos Java y viceversa mediante las implementaciones de patrones repository, 
u otro mecanismo que sea aplicado.

## @Entity
En jmoordb-core las entidades se definen mediante el uso de anotación @Entity.
Las entidades contener Referencias a otras entidades o documentos embebidos
\small
```java
    @Documented
    @Target(ElementType.TYPE)
    @Retention(RetentionPolicy.RUNTIME)
    public @interface Entity {
        String collection() default "";
        String database() default "{mongodb,database}";
        JakartaSource jakartaSource() default JakartaSource.JAKARTA;
    }

```
\normalsize


Anotaciones que se utilizan para definir entidades son las siguientes:

## @Id
- Especifica llave primaria, solo permite dos tipos de datos **String/Long**
- Permite especificar atributos autoincrementable
- @Id(autogeneratedActive = AutogeneratedActive.ON)  : Activa el autoincrementable
  solo para atributos Long.
- @Id(autogeneratedActive = AutogeneratedActive.OFF) : Predeterminado no usa 
  autoincrementable
- Cuando se utilice autogeneratedActive = AutogeneratedActive.ON), debe definir 
  una interface de tipo @AutoincrementRepository, en su paquete de repositorios.

\small
```java
    @Documented
    @Target(ElementType.TYPE)
    @Retention(RetentionPolicy.RUNTIME)
    public @interface Id {
        String value() default "";
        AutogeneratedActive autogeneratedActive() default 
                             AutogeneratedActive.OFF;
    }

```
\normalsize

Ejemplo de como definir entidades con llave primaria de tipo String

\small
```java
@Entity
public class Oceano {
    @Id
    private String idoceano;
    @Column
    private String oceano;

    public Oceano() {
    }
    //set/get
}

@Entity

    @Id

      private String planeta;

    }
```

## @Column
 Define un atributo de la entidad, estos atributos son tipos de datos válidos 

\small
```java
@Documented
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Column {
    String value() default "";
}
```
\normalsize

## @DocumentEmbeddable
- Define una clase que será embebida en una entidad.
- En la entidad que será embebida se usa la anotación @Embedded


\small
```java
@DocumentEmbeddable
public class Idioma {
   private String ididioma;
   private String idioma;

    public Idioma() {
    }
    // set/get
 }
```
\normalsize


## @Embedded
- Define un documento embebido dentro de una entidad

\small
```java
@Retention(RetentionPolicy.RUNTIME)
public @interface Embedded {
    String name() default "";
}

```
\normalsize



En el siguiente ejemplo se muestra una colección de documentos embebidos , jmoordb-core
soporta List<>, Set<> o Stream<> como tipos de colecciones.

\small
```java
@Entity
public class Pais {
    @Id
    private String idpais;
    @Column
    private String pais;
    @Embedded
    private Idioma idioma;
    
    @Embedded
    private List<Musica> musica;
}
```
\normalsize

## @Referenced
- Define documentos Referenciados de tipo simple, o colecciones soportadas como
  List<>, Stream<>, Set<>.
- Define las Colecciones referenciadas  
- Tenga presenta que internamente se guardara como un embebido la colección.  
- Si la referencia se especifica como Embebida, se buscará localmente y no en las 
  colecciones referenciadas, esto es posible, ya que jmoordb-core almacena las
  referencias como embebidos, lo que ofrece mayor velocidad a la hora de hacer 
  consultas. El programador debe encargarse de consultar en las colecciones 
  referenciadas para garantizar que estos estén actualizados.  
- Internamente, se almacenan las colecciones referenciadas como embebidos, pero 
  las búsquedas se hacen en los referenciados, a menos que se indique lo 
  contrario con TypeReferenced.EMBEDDED.
- En el capítulo @Repository se profundiza en la sintaxis y uso. 
 
La anotación Referenced cuenta con la siguiente definición:

\small
```java
@Retention(RetentionPolicy.RUNTIME)
@Target({ElementType.METHOD, ElementType.FIELD})
public @interface Referenced {
 String from();
 String localField();
 TypeReferenced typeReferenced() default TypeReferenced.REFERENCED;
}
```
\normalsize

**Atributos**  
* from: colección foránea
* localField: Campo local que hace referencia a la colección referenciada.  
* TypeReferenced:
  El framework almacena las colecciones referenciadas como un embebido.  
  **ReferenceType.REFERENCED** : Busca en las colecciones referenciadas.  
  **ReferenceType.EMBEDDED**   : Busca la colección con los datos embebidos, no 
  realiza búsquedas en las colecciones referenciadas. Es responsabilidad del
  desarrollador buscar en cada colección referenciada. Ya que si algún documento
  ha cambiado en la colección referenciada, este no se mostrará actualizado.                      

El enum TypeReferenced contiene la siguiente estructura

\small
```java
public enum TypeReferenced { 
   REFERENCED, EMBEDDED     
}
```
\normalsize
Ejemplo de entidad con elementos referenciados 

\small
```java
@Entity
public class Pais {
    @Id
    private String idpais;
    @Column
    private String pais;
    @Embedded
    private Idioma idioma;    
    @Embedded
    private List<Musica> musica;
    @Referenced(from = "planeta",localField = "planeta.idplaneta")
    private Planeta planeta;
    @Referenced(from = "oceano",localField = "oceano.idoceano")
    private List<Oceano> oceano;   
    
    public Pais() {
    }

```
\normalsize

Ejemplo de entidad con referencias usándolo como **documento embebido**:  
Observe que se utiliza TypeReferenced.EMBEDDED en @Referenced  List<Oceano>, 
se cargaran los embebidos dentro de Pais{} y no se buscara en la colección Oceano.
Para implementar esta funcionalidad debe considerar que si algún documento en 
la colección Oceano fue actualizado nunca se mostrará al consultar
mediante TypeReferenced.EMBEDDED. Esta funcionalidad ejecuta consultas de manera
más rápida. Su desventaja es que no tendríamos los datos siempre actualizados de 
los documentos que se han referenciado.

\small
```java
@Entity
public class Pais {
    @Id
    private String idpais;
    @Column
    private String pais;
    @Embedded
    private Idioma idioma;
    
    @Embedded
    private List<Musica> musica;
    @Referenced(from = "planeta",localField = "planeta.idplaneta")
    private Planeta planeta;
    @Referenced(from = "oceano",localField = "oceano.idoceano", 
                       typeReferenced = TypeReferenced.EMBEDDED)
    private List<Oceano> oceano;
   
    
    public Pais() {
    }

```
\normalsize

```java
    @Referenced(from = "oceano", 
                localField = "oceano.idoceano")
    private Oceano oceano;

    private Profesion profesion;
    @Referenced(from = "planeta",
                localField = "planeta.idplaneta")

                localField = "edificio.idedificio",

    @Referenced(from = "museo",
```
